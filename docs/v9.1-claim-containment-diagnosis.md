## How this page disciplines its own quantity claims

This page names a class of defect — a hand-written quantity-shaped claim on generated-surface
prose that no gate can dispute — and it is itself hand-written prose on a `docs/` page. The
hazard is explicit and stated before any finding below: containment's sole call site (section 1.2)
reaches only `docs/gates/*.md`, and Phase 25's CONTAIN-01 names three further surfaces, none of
which is this page. A diagnosis that names the class while publishing an uncontained count of its
own would be a fresh instance of exactly what it diagnoses. Four commitments follow from that,
adjudicated at D-02's discretion and resolved toward the researcher's lowest-risk recommendation:

1. **Every quantity on this page is a frozen dated measurement, never a current-fact claim.**
   Each number is stated with the date it was measured and the exact command that produced it, so
   a reader re-derives it rather than trusts it. This is the identical treatment
   [`docs/PROCESS.md`](PROCESS.md) §2 already gives frozen historical counts, and it is legitimate
   here for the same reason it is legitimate there: a census reading is closed and immutable *as
   of its date*, and that is the entire content of what this page claims about any number it
   states.
2. **A moving count this page needs to refer to is pointed at, never restated.** Where the page
   needs the battery total, it names the generated source — `CLAUDE.md`'s generated CI-gate table
   and the population-arithmetic sentence beside it — instead of typing a digit. Where a later
   section needs a gate page's own figures, it names that page's `<!-- GENERATED:FACTS -->` fence
   and the key inside it, never the number the fence currently holds.
3. **The disclosed bound is stated, not discovered by a reader working it out.** This page is not
   a member of `LITERAL_SCAN_MD_GLOBS` (`scripts/gen-gate-docs.py`), so CONF-13's standing literal
   scanner does not scan it; and containment's sole call site is scoped to `docs/gates/*.md`
   (section 1.2), so `detail_page_containment_problems` cannot reach this page either — and could
   not usefully if it did, since this page carries no `<!-- GENERATED -->` fence for a claim to be
   compared against. Nothing gates the digits on this page. That is why commitment (1) is a
   written discipline rather than a checked one, and both halves of the bound were re-derived at
   write time rather than assumed:

   ```
   $ /usr/bin/grep -n "v9.1-claim-containment-diagnosis" scripts/gen-gate-docs.py
   (no output; exit 1 — this page's path is not a LITERAL_SCAN_MD_GLOBS member)
   ```

   ```python

   ()
   ```

   Both commands were run 2026-09-09 against the commit named in "Method" below.
4. **The rejected options are named, per D-02.** Two code changes were available and neither is
   taken here, because this phase writes no fix: adding this page to CONTAIN-01's equality floor
   once that floor exists, and registering this page's literals as `_DEFERRED_LITERAL_HITS` ledger
   entries. Phase 25 may take either; recording that choice is Phase 25's, not this page's.

## Method

clean — `git status --porcelain` produced no output before this page was written.

Every reading on this page was taken by one of four methods, named so a reader can repeat it:
direct invocation of the production functions in `scripts/gen-gate-docs.py`, loaded via
`importlib.util.spec_from_file_location` / `module_from_spec` and registered in `sys.modules`

This page cites a symbol plus a re-derivation command, never a bare `file:line`. The reason is
stated plainly rather than assumed: a line citation goes stale on the next unrelated edit made
above it in the same file, while a symbol name and a grep for it stay correct regardless of what
moves around it. This is not a hypothetical risk — it is precisely the defect class dispositioned
for this milestone's own CR-03 in section 3 below, and a diagnosis that cited itself the way CR-03
cites `docs/README.md` would be self-refuting on its own terms.
