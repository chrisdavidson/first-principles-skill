## 1. The mechanism

### 1.1 The exemption, quoted at source

`scripts/gen-gate-docs.py` defines `_CITATION_SHAPE_RES`, a tuple of citation/identifier/transition
patterns that `_strip_citation_shaped_numbers` applies before any count claim is extracted from a
page's prose. One member is the measured-transition vector pattern:

```
$ /usr/bin/grep -n "Measured-transition vector" -A3 scripts/gen-gate-docs.py
1140:    # Measured-transition vector, mirroring HEADLINE-LOCK's own
1141-    # arrow-adjacency rule: a digit immediately next to a transition arrow
1142-    # is a delta, not a current-fact count.
1143-    re.compile(r"\d[\d,]*\s*(?:→|-->|->)\s*\d[\d,]*"),
```

The comment block states the pattern's own intent: it mirrors `HEADLINE-LOCK`'s arrow-adjacency
rule (`scripts/check-traceability.py`) — a digit sitting immediately next to a transition arrow
(`→`, `->`, or `-->`) is read as a **delta**, describing a change, not a **current-fact count**
describing the present state of something. **The exemption is correct in intent.** Narrative prose
must be able to say a number moved from one value to another without every one of those numbers
being treated as an unattributed current claim — the alternative would forbid this project's own
`docs/README.md`-style changelog prose entirely. The finding below is that the exemption is wrong
in **extent**, not that it should not exist.

### 1.2 The span-deletion site, and what follows from it

`_strip_citation_shaped_numbers` applies every `_CITATION_SHAPE_RES` member with `pattern.sub(" ",
text)` — a whole-span substitution, not a partial one. For the measured-transition pattern, the
matched span is the **entire** `N → M` run: both operands and the arrow between them, replaced
with a single space before `_normalise_numbers` ever runs to extract candidate count claims from
what remains.

Follow that mechanically, rather than asserting the conclusion — and verified by direct
invocation rather than by reading the regex and trusting it, because the naive reading is wrong
in a way worth naming. A single continuous span written as one clause, `152 → 182 → 184`, matches
the pattern only **once** (`152 → 182`): `re.sub` performs non-overlapping left-to-right
substitution, so once `182` has anchored the first match it cannot also anchor a second one, and
the terminus `184` survives stripping intact.

```python
>>> _strip_citation_shaped_numbers("a chain `152 → 182 → 184` describes growth")
'a chain `  → 184` describes growth'
```

That is not how this project's own prose states a growth history, though. `docs/gates/CONF-SURFACE.md`
(§3 below) writes its three-hop chain as three separate `N → M` occurrences, one per sentence —
`134 → 152`, then later `152 → 182,`, then later `182 → 184,` — never as one continuous span. Run
against that real text, all three hops match independently and all three numbers, including the
terminus, are stripped:

`_CITATION_SHAPE_RES` holds its members anonymously — there is no bound name for the arrow
pattern in `scripts/gen-gate-docs.py` — so the block below binds it the way
`scripts/census-delta-vectors.py` does, by exact `.pattern` selection out of the live tuple, and
defines the paragraph it runs against by that paragraph's own opening sentence rather than by a
line slice. Setup, run 2026-09-09 from the repository root:

```python
import importlib.util, sys
from pathlib import Path

spec = importlib.util.spec_from_file_location("gen_gate_docs", "scripts/gen-gate-docs.py")
mod = importlib.util.module_from_spec(spec)
sys.modules["gen_gate_docs"] = mod
spec.loader.exec_module(mod)

arrow = next(p for p in mod._CITATION_SHAPE_RES
             if p.pattern == r"\d[\d,]*\s*(?:→|-->|->)\s*\d[\d,]*")

text = Path("docs/gates/CONF-SURFACE.md").read_text(encoding="utf-8")
conf_surface_para = next(para for para in text.split("\n\n")
                         if "**Growth is not barred outright**" in para)
```

```python
>>> [m.group(0) for m in arrow.finditer(conf_surface_para)]
['134 → 152', '152 → 182,', '182 → 184,']
>>> '184' in mod._strip_citation_shaped_numbers(conf_surface_para)
False
```

**Every** number in a chain written the way this project's own narrative prose actually writes
one — one hop per sentence, never chained inline — is therefore removed before counting happens,
including the **terminus**: the final value in the chain, positionally last, the one a reader who
is not tracing the regex takes as the sentence's current count. The pattern was written to stop a
delta from being mistaken for a current-fact claim; its side effect is that it cannot distinguish
the terminus (which readers do treat as current) from every hop before it (which they do not) —
for prose written the way this project actually writes it, whichever position the terminus falls
in gets removed along with the rest.

Containment's reach makes this concrete. `detail_page_containment_problems` is `docs/gates/*.md`'s
containment floor: it splits a page's lines into "inside a generated fence" and "outside" one
(`_generated_line_flags`), strips citation-shaped numbers from both, and reports any number stated
outside a fence with no matching literal inside one. Its **sole call site** is inside `cmd_check()`,
guarded by a `DETAIL_PAGE_DIR in path.parents` test:

```
$ /usr/bin/grep -n "DETAIL_PAGE_DIR in path.parents" scripts/gen-gate-docs.py
2947:        if DETAIL_PAGE_DIR in path.parents:
```

`DETAIL_PAGE_DIR` is `docs/gates/`. This is what scopes containment to the 31 generated detail
pages and nowhere else — a fact section 1.4 below proves by direct invocation, not by reading this
guard and trusting it.

### 1.3 The distinction the exemption destroys

Because the strip removes a stated history's terminus along with every hop before it, containment
cannot tell these two states apart:

**A chain whose final value has gone stale is, to this scanner, bit-for-bit indistinguishable from
one whose final value is current. Both produce the same scanner output: none.**

That sentence is the mechanism-level answer to backlog 999.49's root question, and it is PROSE-01's
own requirement in its own terms: the exemption is not merely under-tested or narrowly missing one
surface, it structurally cannot corroborate a chain's terminus against anything, by the same
whole-span deletion that correctly stops it from flagging the earlier hops.

### Definition: "sibling site"

A **sibling site**, on this page, is a location carrying a delta chain whose terminus is a live
current-fact count corroborable against a named generated source, sitting where no check disputes
it — exactly the union of Appendix A's **G2** (current, terminus corroborated) and **G3** (stale
terminus) rows, and nothing else. The other three grounds are excluded, each for a stated reason:
**G1** (frozen-historical-by-design) is excluded because its vectors sit in a dated, closed record
that does not claim live/current authority — nothing to corroborate against a *present* state; **G4**
(not a quantity claim) is excluded because the match is not a count at all — an identifier, a line or
phase range, a version fragment; **G5** (other, argued individually) is excluded because each such
row is either a non-terminal hop already accounted for by its own chain's separately-adjudicated
terminus row, or — as the primary site above demonstrates — a chain whose true terminus falls
outside this census's digit-only population by construction, argued in its own terms rather than
folded into a count it was never enumerated into.

### The reason, stated as a property of the class

**Primary: no corroborating value exists.** Every mechanism this milestone proposes — the
`N → M` chain-terminus arm (`CONTAIN-02`), the wider surface reach (`CONTAIN-01`), the ledger
reconciliation (`CONTAIN-04`) — works by comparing a claim's stated value to a value read from a
generated source. A consistency-shaped defect, by construction, states no value: it is two
sentences whose *rule* contradicts, not two numbers whose *magnitude* disagrees. Containment could
scan the surface both sentences sit on perfectly, at full reach, with every fence recognised and
every terminus corroborated, and it would still see nothing, because there is nothing shaped like
what it checks. **The falsification test is in the reader's hands, stated plainly: name a
consistency-shaped defect — one rule, stated two contradictory ways, no digit in either
statement — that a value-comparison mechanism would catch. If one exists, this reason is refuted.**
No such example is known to this page's author as of the date above; none was found while
adjudicating Appendix A's 671 enumeration rows, all of which are quantity-shaped by construction (D-09
scoped the census to the digit-only population precisely because that is what is mechanically
enumerable).

**Secondary, named as the only known direction rather than as a proposal.** Corroborating a
consistency-shaped claim requires a semantic judge — reading both sentences and deciding whether
their *rules* agree, a judgement no value-comparison performs. That territory is already named and
already filed: backlog `999.4`, "Semantic claim-to-chain correspondence judging." This milestone
