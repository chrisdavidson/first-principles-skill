## 4. Pass definition

A cell **PASSes** iff all four hold:

1. `run_cell.py` recorded `status: complete` for the cell.
2. `source_unchanged` is true (the frozen source's sha256 inside the scratch
   `.first-principles/` is unchanged after the run).
3. `extra_files` is empty (no file other than the source and the one expected
   `persona-<role>-<UTC>.md` exists in the scratch `.first-principles/` afterward).
4. `python3 scripts/check-persona-view.py <persona file> <source file>` exits 0
   (`PERSONA-GATE: PASS`).

A cell that fails any of the four **FAILs**, with its fail codes recorded as:

- Every distinct `PV-*` code the checker prints (`PV-HEADER`, `PV-WORDS`, `PV-UNCITED`, `PV-ID`,
  `PV-NUMBER`, `PV-BAND`, `PV-SHAPE`, `PV-DEADEND`, `PV-SOURCE` — the closed set
  `scripts/check-persona-view.py` can emit against a persona/analysis pair; `PV-GUIDE-NAME` and
  `PV-GUIDE-WORDS` score the companion reading guide, not a persona view, and do not apply here).
- `NO-FILE` — `status` was not `complete` (no persona file to check, including a refusal or a
  `no_file` run).
- `SOURCE-MODIFIED` — `source_unchanged` was false.
- `EXTRA-FILE` — `extra_files` was non-empty.

## 6. Bar for PDEF-01

The bar is: **>= 11 of 12 cells PASS AND zero cells carrying `PV-ID` AND zero cells carrying
`PV-NUMBER`**.

The bar is evaluated only once all 12 cells have reached a terminal state (`complete` or
`no_file` — not `limit_stub`, which is not terminal). Fewer than 12 completed cells means **"bar
not evaluable"**, stated as such — never reported as "met" on a partial run, whatever the partial
result looks like.

## 7. Stop / resume

A `limit_stub` result (`run_cell.py` exit 3) stops the whole sequence at that cell. The stub cell
produced no observation and is re-run, unchanged, on resume. A cell that reached a terminal state
(`complete` or `no_file`) is never re-run, re-rolled, or replaced, whatever its result — a PASS
stands as a PASS and a FAIL stands as a FAIL.
