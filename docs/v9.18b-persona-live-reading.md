## 4. Pass definition

A cell **PASSes** iff all four hold:

1. `run_cell.py` recorded `status: complete` for the cell.
2. `source_unchanged` is true (the frozen source's sha256 inside the scratch
   `.first-principles/` is unchanged after the run).
3. `extra_files` contains, at most, the one expected PDF companion
   `persona-<role>-<UTC>.pdf` (rendered by the skill's own `## Render the PDF` step, PKG-01, for
   any view that passed its self-check — amended 2026-10-02, see §11). Any other file in the
   scratch `.first-principles/` afterward counts as `EXTRA-FILE`.
4. `python3 scripts/check-persona-view.py <persona file> <source file>` exits 0
   (`PERSONA-GATE: PASS`) — the current, post-87 checker, which now also checks `PV-QUESTIONS`
   and `PV-DIRECTIVE`.

A cell that fails any of the four **FAILs**, with its fail codes recorded as:

- Every distinct `PV-*` code the checker prints against a persona/analysis pair: `PV-HEADER`,
  `PV-WORDS`, `PV-UNCITED`, `PV-ID`, `PV-NUMBER`, `PV-BAND`, `PV-SHAPE`, `PV-DEADEND`, `PV-SOURCE`,
  `PV-QUESTIONS`, `PV-DIRECTIVE` (eleven codes `scripts/check-persona-view.py` can emit against a
  persona/analysis pair, measured at registration time by `/usr/bin/grep -oE 'PV-[A-Z-]+'
  scripts/check-persona-view.py`; `PV-GUIDE-NAME` and `PV-GUIDE-WORDS` score the companion reading
  guide, not a persona view, and do not apply here).
- `NO-FILE` — `status` was not `complete` (no persona file to check, including a refusal or a
  `no_file` run).
- `SOURCE-MODIFIED` — `source_unchanged` was false.
- `EXTRA-FILE` — `extra_files` was non-empty.

## 7. Stop / resume

A `limit_stub` result (`run_cell.py` exit 3) stops the whole sequence at that cell. The stub cell
produced no observation and is re-run, unchanged, on resume. A cell that reached a terminal state
(`complete` or `no_file`) is never re-run, re-rolled, or replaced, whatever its result — a PASS
stands as a PASS and a FAIL stands as a FAIL.
