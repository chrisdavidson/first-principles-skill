## Scope and method

**Section unit — level-agnostic, and why.** Per document, the census level is the shallowest ATX
heading level that carries any of the six prescribed template roles (Problem Essence, Assumptions
Table, Ground Truths, Derivation Chains, Abandoned Reasoning, Conclusion); every heading at that
level, in document order, is a section. A fixed heading-level rule (always `##`, for example)
would have reported all six roles absent on at least one control document that carries the
template one level shallower than the others — a measurement artifact, not a finding. The
level-agnostic rule exists specifically to make that artifact structurally impossible.

**Role mapping.** Pass 1 is exact normalized-title match against the six template titles. Pass 2
is a closed, lettered set of judgment rules applied only where pass 1 does not match: (a)
whole-word containment of exactly one template title, (b) a fixed synonym table, (c) bounded body
inspection — permitted only for a Derivation Chains candidate, looking only for named structural
markers, and never permitted for a Conclusion candidate — and (d) a standing prohibition on using
the heading's stripped ordinal number to assign a role.

**Tiers.** Three, reported separately, never collapsed: CONFORMING (Derivation Chains at position
4 and Conclusion at position 6), RENUMBERED (both roles located, at least one off its prescribed
position), and ROLE-ABSENT (at least one role cannot be located at all). ROLE-ABSENT is kept
distinct so that "the numbering moved" and "there is no locatable conclusion" can never collapse
into the same result.

**Categories.** Seven fixed tags for inserted (non-role) sections: `document-title`,
`process-output`, `scope-note`, `missing-inputs`, `validation-record`, `domain-content`, `other`.
Inserted sections are recorded as position plus tag, never as verbatim heading text, identically
on both corpora.

**Same instrument, both corpora.** The identical mechanical extractor ran on the control corpus
and the real corpus, digest-locked between the two runs so a later reader can be told whether the
comparison is void; the digest-lock mechanics and their own limitation are stated below under
Limitations.

## Verdict

**NOT-WELL-FORMED, ground RENUMBERING.**

The pre-registered rule (`docs/v8.12-section-census-protocol.md`, "Verdict decision rule
(ANCHOR-02)") is stated as integer comparisons over the real corpus alone:

- `L = 0` → NOT-WELL-FORMED, ground ROLE-ABSENCE.
- Otherwise: `k <= 1` → WELL-FORMED, ground POSITIONS-HOLD.
- Otherwise (`k >= 2`) → NOT-WELL-FORMED, ground RENUMBERING.

Applied to the real corpus's own figures: `L = 10`, which is not 0, so the ROLE-ABSENCE ground
does not fire. `k = 3`, and `3 >= 2`, so the rule yields **NOT-WELL-FORMED** on ground
**RENUMBERING**.

**The boundary, restated with the observed value named against it:**

- `k = 0` → WELL-FORMED
- `k = 1` → WELL-FORMED (at the cut)
- `k = 2` → NOT-WELL-FORMED (one step above the cut)
- **Observed: `k = 3`** — one further integer step above the cut than the boundary case itself.

Every comparison above was between integers (`L` against 0; `k` against 1 and against 2). No
rounding operation of any kind entered any clause of the decision rule, so no rounding could have
moved this verdict.

**Control figures printed beside the real figures, and the attribution value.** The control's own
`k` = 8, `L` = 12 (control `k`/`L` = 8/12, 0.7) stand beside the real corpus's `k` = 3, `L` = 10
(real `k`/`L` = 3/10, 0.3). The pre-registered attribution vocabulary is fixed against the
control's own `k` alone: at `k >= 2` the vocabulary resolves to its highest branch, and the
control's `k` = 8 sits there — the attribution value is **PRE-EXISTING**. **Attribution does not
change the verdict stated above.** The verdict is decided on the real corpus alone, per the rule;
the control cannot be used to launder or soften a real-corpus finding, and it was not used that
way here — the NOT-WELL-FORMED verdict was reached from the real corpus's `k` = 3 before the
attribution value was even computed.

**Instrument-validity clause.** The control's own `k` + `a` = 8 + 0 = 8, which is `>= 1`. Per the
protocol, this means the harness corpus every prior positional measurement (the v8.7–v8.11 §6→§4
arc) ran on itself contains documents where positional anchoring mis-locates. That is recorded here
as a limitation on those **prior** measurements — it is not evidence about real use, and it is not
what drove the verdict above.

**Both outcomes are complete results.** A verdict of NOT-WELL-FORMED is not the phase failing and
the alternative would not have been the phase succeeding — either integer outcome of `k` would have
produced a complete, publishable answer to the same question. What follows in this document (the
replacement anchoring) is exactly what the protocol commits this document to publishing under the
verdict actually reached, not a consolation deliverable.

## Anchoring — the replacement, section-role-based procedure

Because the verdict is NOT-WELL-FORMED, the protocol commits this document to publishing the
role-location procedure restated as an application procedure a reader could run by hand on one
document:

1. **Determine the census level.** Read every ATX heading (a line whose first non-whitespace
   characters are one or more `#` followed by whitespace; nothing inside a fenced code block
   counts). The census level is the shallowest level that carries any of the six template roles.
   Headings deeper than that level are sub-structure, not sections; headings shallower than that
   level (most often the document's own title) are likewise excluded — neither a section nor
   sub-structure.
2. **Normalize every heading at the census level:** trim whitespace; strip a leading ordinal prefix
   (a section sign, digits with optional sub-numbers, an optional trailing period/parenthesis/colon
   /hyphen); strip a leading `Phase <digits>` prefix; strip surrounding emphasis markers and
   trailing punctuation; lowercase; collapse internal whitespace.
3. **Pass 1 — exact match** the normalized title against the six template titles (problem essence,
   assumptions table, ground truths, derivation chains, abandoned reasoning, conclusion). A match
   assigns the role; move to the next heading.
4. **Pass 2, only for a heading pass 1 did not match**, apply in this fixed order and stop at the
   first that resolves the heading:
   - **(a) Containment** — the normalized title contains exactly one template title as a whole-word
     substring, and no other template title. Assign that role.
   - **(b) Synonym table** — the normalized title exactly equals a fixed synonym entry (for
     example, a Conclusion synonym such as "recommendation" or "verdict"; a Derivation Chains
     synonym such as "chains" or "reasoning chains"). Assign that role.
   - **(c) Bounded body inspection** — permitted **only** for a Derivation Chains candidate, and
     only to look for a small set of named structural markers (a ground-truth-id prefix, a chain
     arrow glyph, or a chain-label heading of the documented letter-plus-digit form). **Never
     permitted for a Conclusion candidate** — an unresolved Conclusion candidate is recorded as
     unlocatable, never resolved by reading its body.
   - **(d) Never assign a role from the heading's own ordinal number** — the number identifying the
     role is exactly the question this whole census exists to answer, so using it to assign the
     role would assume the answer.
5. **Duplicates and merges, fixed in advance.** Two headings at the census level sharing a
   normalized title are separate sections at distinct positions; if both map to the same role, the
   role takes the **first occurrence** in document order. A single heading whose normalized title
   contains two distinct template titles is assigned to **both roles at that one shared position**
   (recorded as `merged-role`).
6. **Where a role cannot be located at all** — no heading at the census level satisfies pass 1 or
   any pass-2 clause for that role — the document is coded **not-codeable** under this anchoring for
   that role. This is reported **separately**, distinct from a document whose roles are simply
   renumbered, and it is **never silently dropped** from Phase 180's denominator: a not-codeable
   document still appears in Phase 180's accounting, tagged with its disposition, rather than
   quietly vanishing from the count.

The real corpus already contains a concrete instance of this disposition: one in-denominator
document locates neither role under any pass and is recorded ROLE-ABSENT — not smoothed into an
adjacent tier, not dropped from the count. That is what "not-codeable, reported separately, never
dropped" looks like applied, not only stated.

## Blindness boundary

The census reads heading level, position and normalized title only. The mechanical extractor
renders no body text under any circumstance. Body inspection occurs exclusively under pass-2 clause
(c), bounded to a Derivation Chains candidate and to the named structural markers, and is logged
every time it fires. Across **both corpora combined, the clause-(c) inspection count is 0** —
control 0, real 0 — because every located Derivation Chains role on both corpora resolved under
pass 1 (exact match) or pass-2 clause (a) (whole-word containment); no document on either corpus
presented a Derivation Chains candidate ambiguous enough to require body inspection. **No Conclusion
body text was read anywhere in this phase**, on either corpus, under any clause. This is why the
Phase-180 pre-registration remains blind to what the conclusions actually say — the census this
document reports on never looked.

## Limitations, stated not glossed

**Author-auditable, not reader-auditable.** The per-document census table — every row's tier,
positions, category tags and notes — lives in the working-set record outside git, because the
corpus is client work. This document carries aggregates only. A reader can check every arithmetic
step shown above; a reader cannot re-derive it from the underlying rows, because those rows are not
published. This is the first milestone in this project's history with that limitation, and it is
stated here rather than left implied.

**The identical-instrument claim has the same limitation, and it is the more load-bearing one.**
The mechanical extractor was digest-locked (SHA-256) between the control census and the real
census, and the working-set record states that the digest was re-checked and matched before the
real census began. That digest value, and the assertion that it was checked, both live in the
working-set record — **outside git**. A reader cannot confirm from anything in this repository that
the digest check actually fired, or that the extractor was unmodified between the two runs; that
claim rests on the author's attestation and on the executing agent halting on a mismatch at the
time it ran, not on anything reconstructable from `git log`. This matters more than the
per-document limitation above, because the same-instrument property is the entire premise the
control census exists to protect — if the two corpora were not censused by the identical rule, the
comparison in the Verdict section above is void, and a reader has no independent way to check that
it was not.

**Version/date spread, not stratified.** The real corpus spans four distinct dispatch dates across
11 in-denominator documents (cell sizes 1/8/1/1); the control spans two distinct generation dates
across a 6/6 split. Neither spread supports a meaningful stratified rate at these cell sizes, so
none is computed, per the D-02 figures reported above.

**The clause-(c) asymmetry can only push toward ROLE-ABSENT.** Because clause (c) gives a
Derivation Chains candidate one location route a Conclusion candidate structurally cannot have (body
inspection is barred for Conclusion by the blindness boundary itself), this asymmetry can only push
a document toward ROLE-ABSENT — it can never resolve a document away from ROLE-ABSENT that clause
(c) was not applied to. On this census the asymmetry was never actually exercised (0 clause-(c)
calls on either corpus), so it had no effect on the figures above, but the asymmetry in the rule
itself is a standing limitation on the instrument, not only a possibility.

**Where a heading resisted every clause.** On the real corpus, exactly one in-denominator document
(reported in the Figures section as the corpus's single ROLE-ABSENT case) has no heading at any
level that satisfies pass 1 or any pass-2 clause for either governing role; its structure was
checked against every available clause and none resolved it. No control-corpus document reached
this outcome; the control's 0 ROLE-ABSENT figure above is exact, not rounded.

**Sample concentration — disclosed, not adjusted.** The 11 in-denominator real documents are not 11
independent observations. Their distribution across the four labelled projects is 8 / 1 / 1 / 1 —
eight of the eleven documents come from a single labelled project. The `7/11` CONFORMING figure
reported above should not be read as seven independent confirmations; it is heavily shaped by one
project's house style for structuring these documents. The protocol pre-registered no clustering or
independence statistic, and no per-project denominator, clustered rate, or adjusted verdict has been
computed or substituted for the figures reported above — doing so now, after the figures exist,
would itself violate the pre-registration discipline this whole document depends on. This
concentration is disclosed as a limitation on how the aggregate should be read, not as a change to
the aggregate itself. One observation about robustness, which follows from figures already reported
above and is stated as an observation rather than a new decision rule: RENUMBERED tiering appears in
more than one labelled project (not concentrated in the same single project that supplies most of
the CONFORMING count), so the `k >= 2` comparison that drives the verdict above does not depend on
any single project's documents alone.
