# v8.7 Quality Baseline Freeze — Phase 164 Verdict

**Phase:** 164-harness-promotion-baseline-freeze. **Recorded:** 2026-07-22. **Status:** the
phase's write-up — cites committed evidence, does not recompute it.

## What this is, and what it cost

Phase 164 promoted the throwaway blind A/B rig behind `docs/v8.6-quality-ab-experiment.md` into
a permanent, self-testing instrument (`scripts/check-quality-harness.py`), froze a pre-fix
baseline Phase 166's post-fix comparison can honestly be made against, and measured — for the
first time in this project's history — whether its own LLM-judged results reproduce.

**This phase spent nineteen live `claude -p` invocations, not eighteen.** The breakdown: **one**
Wave-0 D-22 transport probe (`tests/quality-probe-v8.7/`), **six** fresh generations, **six**
fresh judgings, and **six** channel-matched re-judgings of the Phase-162-frozen corpus — 1 + 6 +
6 + 6 = 19. `tests/quality-baseline-v8.7-regenerated/manifest.tsv` records 18 rows (the
generation + fresh-judging + re-judging arms of Plan 04's single `--run --rejudge` invocation,
each row outcome `completed`, zero re-dispatches); the 19th invocation is the D-22 probe, spent
in Plan 01 before any extraction code existed and recorded separately in
`tests/quality-probe-v8.7/README.md`. `164-CONTEXT.md`'s own stated figure of **eighteen**
invocations predates the D-22 amendment that authorised the probe — it is not wrong so much as
written before the probe was added to the plan, and this document states the corrected total
rather than quietly carrying the smaller number forward. Nineteen is the honest total, not a
budget overrun: this is the milestone's first live-spend phase, following a zero-generation
Phase 162 and a fully offline Phase 163.

## The instrument

`scripts/check-quality-harness.py` owns the full generate → extract → blind → judge → tabulate →
detect chain end-to-end in one scripted `claude -p` subprocess composition (`--run`), plus a
byte-faithful re-judge of an existing analyses directory (`--rejudge`), a zero-side-effect
invocation enumerator (`--dry-run`), and a resumable re-dispatcher that never re-sends a
completed invocation (`--resume`). Its offline `--self-test` covers eight labelled items —
extraction guardrail A, extraction guardrail B, the scoreline parser, blinding integrity,
tabulation arithmetic, baseline-fixture integrity (both `tests/quality-baseline-v8.7/` and
`tests/quality-baseline-v8.7-regenerated/`), the mechanical defect detector, and the run-layer
composition itself — and exits 0 under both `python3` and `python3 -O`, with no bare `assert`
(`grep -cE '^\s*assert ' scripts/check-quality-harness.py` returns `0`). It is now battery gate
`QUAL-01`, registered through the existing `gate()` helper in
`scripts/check-firewall-battery.sh`, which moves from fifteen tallied gates to sixteen. `QUAL-01`
is what keeps these eight self-test items firing after this phase ends — a harness that nothing
runs decays, and both the new gate and the extended `FROZEN-EVIDENCE` path-list coverage were
proven to fail when they should (renaming the harness turns `QUAL-01` red; appending a byte to a
file under the regenerated baseline turns `FROZEN-EVIDENCE` red; both revert to green).

**The two guardrails, as implemented, and what each rejects:** Guardrail A rejects reading the
analysis from anywhere other than the stream event carrying the subagent's verbatim output for
the matching Agent `tool_use.id` — never the top-level `result` field, which is an orchestrator
paraphrase. Guardrail B rejects a run carrying more than one Agent dispatch of
`first-principles:first-principles`, not more than one `tool_result` block — a subagent using any
internal tool legitimately produces extra unrelated `tool_result` events, and counting those would
falsely reject well-formed runs.

## The probe (D-22): why "read the `tool_result`" would have been the wrong assertion

Before any extraction code was written, a single Wave-0 `claude -p` invocation
(`tests/quality-probe-v8.7/`) settled which stream event actually carries the verbatim analysis
under this harness's own transport, because the original wording — "read the `tool_result` whose
`tool_use_id` matches the Agent `tool_use.id`" — described the **synchronous** Agent-tool
transport of an interactive session, not the **asynchronous** dispatch a headless `claude -p`
subprocess produces.

The probe's capture was 78,597 bytes (76.7 KB) over 16 JSONL lines — smaller than the plan's own
">100 KB" acceptance bar, which this phase's own read of the capture found miscalibrated: the
capture is complete (the subagent made zero internal tool calls, so there was nothing to inflate
the byte count, and all six output-contract sections are present in full), and structural
six-section presence is the check that actually matters, not a byte floor. The plan's Task 2
verification text also specified `grep -l 'api_error_status'` to identify error stubs during
`--resume` — but that field is present, usually `null`, on every terminal event including every
healthy one, so a `--resume` driven by that literal grep would have re-dispatched all eighteen
successful captures (the T-164-18 tampering threat this phase's threat model names). Both were
caught and corrected before any live spend depended on them, and are recorded here as evidence
the phase's own review caught its own plan defects, not swept past them.

The probe's finding: the matching `tool_result` was **not** the ~200-character
`"Async agent launched successfully…"` stub that 37 other committed `.jsonl` captures under
`tests/step0-captures-v*/` show for this same event type — in this run it carried the full
analysis, plus a 197-character trailing metadata tail. The **primary** channel that reliably
carries the clean, tail-free verbatim text is the `system`/`task_notification` event's `summary`
field, matched by `tool_use_id` against the Agent dispatch's `tool_use.id` — 17,717 characters in
this capture, containing all six output-contract sections, with no trailing metadata. The
guardrails' channel names were amended to follow the probe's finding; the guardrails' **intent**
— never trust the top-level `result` field, never concatenate multiple dispatches — was
unchanged by the amendment. The top-level `result` field was confirmed **not** the analysis: 2,993
characters against a 17,914-character `tool_result` (16.7%), opening with the false claim "Its
output, verbatim in substance" while actually paraphrasing — Guardrail A's rejection of that
field is empirically vindicated, decisively, by this project's own capture.

## The regenerated baseline

The baseline is a single arm at three problems × two runs = six generations, not a second A/B
arm — Phase 166 compares pre-fix vs. post-fix, not 590-vs-612, so the original experiment's second
arm was unnecessary and its budget was reallocated to **within-condition repeats**.

**Why two runs per problem, not one:** the source experiment
(`docs/v8.6-quality-ab-experiment.md`) ran exactly one run per cell, and its own authors called
the resulting exact 35/35 band-total tie between arms "partly luck" — a single run per condition
cannot distinguish a real effect from ordinary run-to-run variation. Spending the budget on a
repeat within each condition instead buys a noise floor: if two pre-fix runs of the same problem
already differ by several band points, an equally small post-fix "improvement" in Phase 166 is
not yet distinguishable from that same run-to-run variation.

**The figures** (from `tests/quality-baseline-v8.7-regenerated/README.md` and its `scorelines.tsv`
/ `rejudge-scorelines.tsv` / `defect-incidence.tsv` / `manifest.tsv`; none of these was a target):

- **18/18 invocations completed**, zero error stubs, zero re-dispatches.
- **Aggregate band total: 85 / 108.** **Pass split: 6 PASS / 0 FAIL** — zero D-14
  derived-vs-stated verdict disagreements and zero `UNPARSEABLE` cells across either scoreline
  file, across all twelve judged rows (six fresh + six re-judge).
- **Per-analysis totals** (of 18 each): Q-P1-run1 = 14, Q-P1-run2 = 15, Q-P2-run1 = 15,
  Q-P2-run2 = 14, Q-P3-run1 = 12, Q-P3-run2 = 15.
- **Per-criterion column sums** (of 18 each, six analyses): C1=18, C2=11, C3=17, C4=12, C5=12,
  C6=15.
- **Defect incidence** over these same six fresh analyses: `untraced_flag` 6/6, `verdict_flag`
  5/6 (Q-P2-run1 is the one clean document in this baseline), `chain_flag` 6/6.

**Within-condition noise floor:** Q-P1 spread 1 (14→15), Q-P2 spread 1 (15→14), **Q-P3 spread 3**
(12→15) — the maximum within-problem run-to-run spread, on the same prompt, same agent body, same
judge channel. Q-P1 and Q-P2 both show a narrower spread of 1, so the floor is not uniform across
problems: **Phase 166 should read each problem's post-fix movement against its own row here, not
against a single project-wide number**, and a movement on Q-P3 smaller than roughly 3 band points
cannot yet be told apart from this baseline's own noise on that problem.

## Reproducibility — the headline finding

This is its own section, not a footnote, because it is the first time in this project's history
that anyone has measured whether its LLM-judged results reproduce, and the number is not small.

The six Phase-162-frozen analyses (`tests/quality-baseline-v8.7/analyses/`) were re-judged
through this run's own `claude -p` channel, byte-unchanged (including their trailing
transport-metadata tail — the re-judge received the frozen corpus exactly as committed, an
asymmetry against this baseline's own freshly-extracted analyses, which carry no such tail per
the D-22 probe's `task_notification.summary` channel). Original scoreline (Phase 162, Agent-tool
channel) side by side with the re-judged scoreline (this run, `claude -p` channel), per document:

| Document | Original /18 | Re-judged /18 | Cell agreement | Delta | Verdict |
|---|---|---|---|---|---|
| condB-P2 | 10 | 11 | 5/6 | +1 | FAIL → FAIL |
| condA-P1 | 12 | 14 | 4/6 | +2 | PASS → PASS |
| condB-P1 | 12 | 14 | 4/6 | +2 | PASS → PASS |
| condB-P3 | 13 | 14 | 5/6 | +1 | PASS → PASS |
| condA-P2 | 11 | 12 | 5/6 | +1 | **FAIL → PASS (VERDICT FLIP)** |
| condA-P3 | 12 | 12 | **6/6 (exact)** | +0 | PASS → PASS |

- **Aggregate: 70/108 → 77/108 (delta +7).** **Pass split: 4 PASS/2 FAIL → 5 PASS/1 FAIL** — one
  document (condA-P2) flipped FAIL to PASS on re-judging, with **no change whatsoever** to its
  underlying text.
- **Only 1 of 6 documents (condA-P3) reproduced its full six-band vector exactly.** Cell-level
  agreement across all 36 scored cells: 29/36 (80.6%). Per-criterion agreement: C1 6/6, C2 5/6,
  C3 5/6, **C4 3/6**, C5 6/6, **C6 4/6** — chain rigor (C4) is the least reproducible criterion.
- **The deltas are directional, not symmetric noise.** Five of six documents moved up
  (+1, +2, +2, +1, +1); the sixth moved by exactly zero. **None moved down.** A judge reproducing
  its own scoring at random would be expected to move some documents down as often as up; this run
  shows a one-sided drift toward higher bands on byte-identical input, not variance scattered
  around a stable mean.

**What a divergence of this kind means:** re-judging six unchanged documents through the same
channel, on a different day, moved the aggregate by +7 band points out of 108 and flipped one of
six verdicts, with zero change to the text being scored. **A Phase 166 post-fix aggregate
improvement smaller than roughly this magnitude (order +7/108, one verdict flip) cannot be
distinguished from re-judging the same documents on a different day.** This is not a defect in
this run — honesty-not-score forbids re-rolling a measured result — it is a real finding about
how much weight every live, LLM-judged measurement this project has ever taken deserves. Phase 166
must read its own aggregate delta against this floor, not treat any positive movement as proof the
fix worked.

## Defect incidence and the Goodhart guard (D-21)

The mechanical detector (`detect_defects`) is calibrated against the Phase-162-frozen corpus in
`tests/quality-fixtures-v8.7/calibration-v8.6-corpus.md`, against the only human-equivalent
reading that exists — the independent judges' own findings in
`docs/v8.6-quality-ab-experiment.md`'s "Finding 3". The calibration **agrees** on two of the three
covered families (untraced Conclusion claims 6/6 vs. 6/6; Verdict-vocabulary violations 6/6 vs.
6/6) and **disagrees** on the third (malformed Derivation Chains: detector 6/6 vs. judges 4/6 —
recorded as a scoping difference, where the detector applies the prescribed chain form more
literally and more uniformly than the judges evidently did, and is not tuned to match the judges'
number). The detector covers three of the source experiment's four reported defect families
(Verdict vocabulary, untraced conclusions, malformed chains); it does **not** cover the fourth —
the near-absent `[Assumes: X]` inline token — because that is a content-aware reading of whether a
derivation step introduces an undeclared assumption, which this structural parser cannot do
without becoming the kind of whole-document semantic reader it was deliberately built not to be.

**The Goodhart guard is a binding obligation on Phase 166's verdict, not an optional aside.**
Phase 165 will be written with this detector's definitions visible — the classic setup for
satisfying the form of a fix without repairing the substance. Phase 166 is therefore required to
report defect-count movement and rubric band-score movement **together**, and to name the
Goodhart signature explicitly if it appears: **defect counts falling while the C2 (Verdict
vocabulary), C4 (chain rigor), and C6 (Conclusion traceability) bands do not move.** A drop in
`untraced_flag`/`verdict_flag`/`chain_flag` with no corresponding lift in C2/C4/C6 across
`scorelines.tsv` would mean Phase 165 satisfied this detector's specific definitions without
producing analyses a rubric-scoring judge would call better — the precise failure mode this
calibration exists to make visible, not to prevent on its own.

## Honest limits

What this instrument does not measure, stated plainly so Phase 166 does not claim more than the
evidence supports:

- **Three of the four reported defect families**, not all four — the `[Assumes: X]` inline-token
  omission is not mechanically detected.
- **Three problems at two runs each**, not a broad sample — six generations total, with a
  measured noise floor of up to 3 band points on one of the three problems.
- **One judge per document**, not an inter-rater panel — the reproducibility finding above measures
  the same judge re-scoring itself, not agreement between independent judges.
- **A four-level scale** (Rigorous/Sound/Hand-wavy/Absent) with two of its six criteria carrying
  the least reproducible readings (C4 at 3/6, C6 at 4/6) in the measurement above.
- **Phase 162's standing finding that rubric conformance does not predict correctness**
  (`docs/v8.7-correctness-spot-check.md`): a document that passed the rubric with the worst
  arithmetic accuracy in its corpus, and a document that failed the rubric with flawless
  arithmetic, both exist in that phase's evidence. A rising band score is therefore not, by
  itself, evidence that an analysis got more *right* — only that it reads as more structurally
  conformant to a judge applying this rubric on this day.

Given all of the above, a Phase 166 verdict that presents this instrument as more decisive than
these numbers support would be the same failure mode Phase 164 exists to prevent in the opposite
direction.
