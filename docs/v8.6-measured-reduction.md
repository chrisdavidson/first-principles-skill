## 3. Per-Technique `## Procedure`-Slice Breakdown (all four compressed techniques)

Each technique's `## Procedure` slice is extracted with the same regex the offline
doctrine/marker-pin checks use (`^## Procedure\n.*?` up to the next `^## ` heading or end of
file — this includes the technique's `-detail.md` pointer block and any trailing separator, so
the same slicing convention applies identically before and after, and any residual noise is
absorbed on both sides of the delta rather than only one). The re-derivation command
(`proc_lines.py`, a 6-line stdin filter applying that exact regex) is shown once, then invoked
per file:

```
$ cat proc_lines.py
import re, sys
PROCEDURE_RE = re.compile(r"(^## Procedure\n.*?)(?=^## |\Z)", re.MULTILINE | re.DOTALL)
text = sys.stdin.read()
m = PROCEDURE_RE.search(text)
lines = m.group(1).split("\n")
if lines and lines[-1] == "":
    lines = lines[:-1]
print(len(lines))
```


**Word-count context (supplementary, not blended with the line-count figures above per D-01).**
Because `shared/references/*.md` is manually hard-wrapped at roughly 90 characters, prose
compression that merges sentences can shrink word count substantially while shrinking line count
only modestly — the wrap absorbs some of the saving. Both measures are shown, kept strictly
separate, so the smaller line-count deltas for `five-whys`/`fishbone` are not mistaken for a
smaller compression effort:

| Technique | Before words | After words | Δ words | % word reduction |
|---|---:|---:|---:|---:|
| `estimate` | 379 | 262 | −117 | 30.9% |
| `theoretical-limit` | 395 | 285 | −110 | 27.8% |
| `five-whys` | 325 | 290 | −35 | 10.8% |
| `fishbone` | 286 | 251 | −35 | 12.2% |

The `estimate`/`theoretical-limit` word-reduction figures match `158-01-SUMMARY.md`'s reported
30.9%/27.8% exactly, confirming the same measurement method is applied consistently across both
phases. `five-whys` and `fishbone` land at a visibly smaller percentage — this is the honest
consequence of Phase 159's own stated discipline (PLAN.md's prohibitions): marker survival and
rule-quantifier preservation are the hard constraint on these two files, not a percentage floor.
Both files carry pinned detector-vocabulary literals (the 4 causal markers plus the
irreducibility-drill logic for `five-whys`; the 7 detector markers for `fishbone`) that must
survive byte-for-byte, which caps how much can be safely trimmed relative to
`estimate`/`theoretical-limit`, which carry no emission detector at all.
