## Methodology

The v8.0 closure terms state that "any future work is a fresh project decision." v8.1 (shipped
2026-07-16) exercised that clause once already — an external-review triage that landed 7 items and
terminally dispositioned 19 as WON'T-DO, each with a recorded rationale in
[`docs/v8.1-grok-review-assessment.md`](v8.1-grok-review-assessment.md). This document exercises the
same clause a second time: it re-opens those 19 terminally-dispositioned items as a fresh project
decision, under a deliberately skeptical bar, to determine whether any rationale has gone stale or
whether the terminal disposition should stand.

This is **not** a re-litigation in the user's favor and **not** a search for reasons to implement
more Grok items. The governing decisions (from
[`146-CONTEXT.md`](../.planning/phases/146-deep-investigation-fresh-verdict/146-CONTEXT.md)) are:

- **D-01 — Uniformly skeptical posture.** Default is keep-won't-do for all 19 items. The
  investigation does not start each item as an open proposal; the inherited presumption is that
  v8.1's rejection holds until the item earns otherwise.
- **D-02 — Value + feasibility bar for promotion.** An item becomes promote-candidate only if the
  fresh investigation shows BOTH (a) clear user/project value AND (b) feasibility within realistic
  constraints (offline-capable, and either no byte-freeze relaxation OR the relaxation cost
  explicitly named). Rationale collapse alone is not sufficient — the value case must also stand on
  its own.
- **D-03 — Ties go to keep-won't-do.** Borderline items that don't clearly clear the value+feasibility
  bar stay won't-do. The verdict enum is closed and two-valued: **keep-won't-do** or
  **promote-candidate**. No middle/conditional verdict exists in this document.
- **D-04 — Blind investigation.** No pre-supplied leaning on any specific item; every verdict is
  formed purely from fresh evidence plus the agreed bar.
- **D-05 — Zero promote-candidates is an acceptable, honest outcome.** If all 9 items in this plan
  (or all 19 across both plans) hold as keep-won't-do, that is a legitimate result, not a failure to
  find something to promote. No promote is manufactured to hit a target count.
- **D-06 — Every v8.1 evidence command is re-run fresh this session.** No cell below cites the
  cached v8.1 result or memory; every `[VERIFIED:` tag reflects an actual command executed during
  this Phase 146 session, with the real output quoted inline. Where the fresh output differs from
  the v8.1-cited value (e.g. README.md has grown a few lines, or gained badges since v8.1 landed
  GROK-06), that drift is called out explicitly rather than silently absorbed.
- **D-07 — Three evidence classes.** `[VERIFIED: repo]` (local shell command), `[VERIFIED: gh]`
  (read-only GitHub CLI), `[VERIFIED: web]` (WebSearch/WebFetch, cited with URL + access date). All
  three are offline with respect to `claude` spend — no live `claude` invocation is used anywhere in
  this document.
- **D-08 — Byte-freeze is a fixed constraint, not a debate.** The detector marker counts
  (pre-mortem 9 / fishbone 7 / inversion 13 / trade-off 10), `MIN_HEADER_HITS == 2`,
  `_COMPOSER_FOCUS_CEILING == 4`, the v7.8 guard column + stay-in-composer tiebreaker, all frozen
  baselines/captures v5.0–v7.13, and the agent body (`shared/spine/SKILL-body.md` /
  `first-principles/agents/first-principles.md`) stay byte-unchanged throughout this document. Where
  an item would require relaxing byte-freeze, this document costs that relaxation as a **finding**
  for a future milestone decision — it never relaxes byte-freeze and never forms a standing opinion
  on whether it *should* persist (that question is explicitly out of scope, D-08 in 146-CONTEXT.md).
- **D-09 — Tiered depth.** Shallow-confirm treatment for near-airtight already-done/infeasible items
  (GROK-01, 07, 09, 11, 13 in this plan); deep-dive treatment for the genuine-gap and
  checkpoint-non-selection items where a fresh verdict could plausibly move (GROK-04, 08 in this
  plan; GROK-10, 12 are also deep-dive per the plan's task split, covered below). Every item,
  regardless of tier, still covers all four INVEST-01 facets: real feasibility, honest effort/cost,
  byte-freeze relaxation cost (if any), and value delivered.
- **D-10 — Prose + bold verdict.** Each item is a `### GROK-NN` subsection ending in a bold verdict
  line; promote-candidates append a non-binding future-milestone scope sketch (VERDICT-02).
- **D-11 — Ascending GROK-NN order**, matching the v8.1 read-order, for direct 1:1 cross-reference
  against `docs/v8.1-grok-review-assessment.md`.
- **D-12 — Filename `docs/v8.2-grok-reassessment.md`** — a neutral name, not the "wont-do" example
  name from INVEST-01 (which was illustrative only), because a "wont-do" filename would misdescribe
  any promote-candidate this document might contain.

A note on scope: GROK-02, 03, 05, 06, 18, 22, 24 (the 7 approved v8.1 items) are already DONE and
are not re-investigated here — they are out of scope by definition (the milestone re-opens only the
19 *not-approved* items). GROK-18 and GROK-24 shared one underlying fix (CONTRIBUTING.md); both are
DONE.
