## 1. Target and Origin

the skill surface. It comes from `v8.4-implementation-readiness-eval.md`'s §4 per-section boundary

## 3. Agent-Surface Measurement (SPLIT-02)

The agent surface — the single assembled `first-principles/agents/first-principles.md` body —
moved from **598** lines before the split to **612** lines after, a change of **+14**.

```
$ git show 5373100:first-principles/agents/first-principles.md | wc -l
598
$ wc -l < first-principles/agents/first-principles.md
612
```

Per **D-02**, this +14 is characterised as **cost-of-mechanism, not regression**. The agent body
inlines each technique's `## Procedure` section only via `{{TOOL:slug}}` — it never carried
`Example`, `Failure modes`, or `Handoff` content for any technique, split or not. The split
therefore had no saving available on this surface; there was nothing here to shrink. What the +14
buys is a load path the agent surface previously lacked entirely: a named pointer to each split
technique's `-detail.md` companion, wired by Phase 154's on-demand load mechanism (MECH-01/02).

The arithmetic is shown openly rather than asserted: four pointer blocks were added, one per split
technique (five-whys, theoretical-limit, estimate, fishbone), at **+5 lines each** = **+20 lines**,
net of **6 separator lines** that Phase 154's split removed elsewhere in the assembled body's
Companion Techniques section. 20 − 6 = **14**, matching the measured before/after delta exactly.

Budget position stated alongside, per SPLIT-03: the agent body sits at **612 of 644** lines, with
**32 lines of headroom**. Trimming the agent body is explicitly out of this phase's scope; this
+14 is not presented as a defect to be fixed.

## 5. Table-of-Contents Disposition (SC-2)

Per **D-05** of `155-CONTEXT.md`, the >100-line guidance threshold applies to core reference files
only, read strictly rather than generously:

- `shared/references/five-whys.md` was over the threshold with no table of contents and gained a
  three-entry anchor one (`When to reach for this` / `Procedure` / `Stop test`), landing at **116**
  lines after the addition (Phase 155 Plan 01).
- `shared/references/fishbone.md`, at **120** lines, already carried a conforming three-entry table
  of contents matching its headings and was verified rather than edited.
- `shared/references/theoretical-limit.md` (**98** lines) and `shared/references/estimate.md`
  (**91** lines) both sit under the threshold and received nothing — the threshold is read
  strictly, not "at or near."

**Convention exception, recorded per D-06.** The three `-detail.md` companion files Phase 154's
split created all exceed the same >100-line convention, and this was surfaced and considered:

| Detail file | Lines |
|---|---:|
| `shared/references/five-whys-detail.md` | 126 |
| `shared/references/theoretical-limit-detail.md` | 108 |
| `shared/references/estimate-detail.md` | 105 |

A table of contents was **deliberately declined** for all three. The reason: Phase 154's D-08
fixes `-detail.md` file content as verbatim moved sections — "no H1, no back-pointer, no new
prose" — with the stated rationale of keeping the split purely editorial so that this phase's line
arithmetic stays exact against `v8.4-implementation-readiness-eval.md` §4's table. Adding a table
of contents to any of the three would both break the no-new-prose property Phase 154 fixed and
perturb the exact 406 upper-bound total this document measures against, and would re-open a
decision one phase old.

This inconsistency is carried **openly, not silently**: the three core files under the threshold
have no table of contents by design, the two core files over the threshold have one, and the three
detail files over the threshold have none — a knowingly asymmetric outcome. A future milestone that
wants detail-file navigation must reopen Phase 154's D-08 explicitly; this document does not do
that here.
