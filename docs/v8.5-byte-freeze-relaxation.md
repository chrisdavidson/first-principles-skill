## 1. Scope and Standing

This is a **named standing rule**, not a one-off v8.5-scoped exception. It carries no expiry
date. A future milestone reads this record the same way it reads
[`v8.0-final-closure.md`](v8.0-final-closure.md) — as a durable disposition, not a temporary
grant that lapses when v8.5 ships.

The rule is a **subtraction record against a default-frozen baseline**. Anything not explicitly
listed in §2 below remains frozen and gating by default. Silence never means permission — a
future milestone that wants to touch something not named in §2 must author its own successor
record per the procedure in §4, not read this document's silence as authorization.

## 2. What Is Relaxed

Exactly two items. No more.

**1. Live re-measure of RR-108-04 and RR-108-05.**
`v8.0-final-closure.md`'s ACCEPTED-FINAL disposition of "no further live re-measure" is
re-permitted for exactly these two residuals:
- **RR-108-04** (S-P10 estimate, true K/N 0/5 on v7.13 live)
- **RR-108-05** (S-P14 theoretical-limit, true K/N 0/5 on v7.13 live)

What this does and does not imply: the v8.0 terminal record stands as accurate for what was true
at the time it was written — this relaxation does not reframe that record as having been wrong.
The residuals' *documented honest state* may be updated by a new measurement, but
honesty-not-score (the project's global D-01) continues to bind without exception: a re-measure
records the true K/N whatever it turns out to be, and a worse result than 0/5 is never a reason to
withhold, soften, or re-frame the recorded outcome.

**2. Reference-file content for the four split files.**
Content, structure, and file count may change for exactly these four files, per the

`v8.4-implementation-readiness-eval.md` is the governing implementation spec for this item —

## 3. What Remains Frozen and Still Gating

Everything below stays byte-frozen. Each line names the exact value and the gate that enforces
it.

- **Detector marker counts** — pre-mortem 9, fishbone 7, inversion 13, trade-off 10 — asserted as
  drift guards inside the BATT-06 offline self-test (`check-routing-battery.py --self-test` →
  `_battery_core.self_test_boundary()`).
- **`MIN_HEADER_HITS == 2`** — the marker-count barrier the BATT-06 sentinels assert against.
- **`_COMPOSER_FOCUS_CEILING == 4`** — asserted load-bearing by the RR-77-08 lock-only
  anti-masking boundary sentinel.
- **The v7.8 trigger-layer fix** — the guard column and the stay-in-composer tiebreaker in the
  agent body's phrase-detection rules (`shared/spine/SKILL-body.md`).

**Sensitivity note.** Splitting reference-file content can perturb the marker corpus the fishbone
detector counts against — `classify()` reads its 7 markers from Step 0 output *text*, and a split
can change which of those markers a run's text contains without changing the frozen count itself.
This is precisely why the marker counts stay frozen and gating while content is relaxed: the
constant is not proof that behavior is untouched, and a future re-measure must check this
explicitly rather than assume it away.

## 4. Relaxing Anything Further

A future milestone that wants to relax anything beyond §2 must follow this procedure:

1. **Name the specific constant, sentinel, or disposition** to be relaxed — no broad or
   ambiguous grants.
2. **State the measured evidence** motivating the change — the same honesty-not-score discipline
   this record follows.
3. **Author a successor governing record** that names this document and states exactly what it
   supersedes.
4. **Leave this record byte-intact.** In-place edits to a prior milestone's terminal or governing
   record are never an acceptable substitute for a successor record — this is the same append-only
   discipline `v8.0-final-closure.md` and `requirements-traceability.md` follow in their own
   addenda.
