# v8.12 — Coding Protocol: Claim Unit, Traces-Back Test, Verdict Vocabulary and Aggregate Rule

**This document is pre-registered and immutable.** It is authored and committed alone, in its own
dedicated commit — the phase's ordering anchor — strictly **before** any document on either corpus
(the frozen harness control or the real corpus) is opened for coding. Once committed, this protocol
is never edited to match what a later coding finds. Any amendment discovered necessary afterward is
recorded as a new, dated addendum appended below the original text, never as a silent rewrite of the
rules that follow — the same discipline `docs/v8.12-section-census-protocol.md` and
`docs/v8.12-corpus-triage-protocol.md` demonstrate.

**Authored blind.** No document in the real working-set analyses directory, and none in either
frozen baseline analyses directory, has been opened while writing this protocol. This document
records rules only.

**Discretion resolved at Task 1.** Five choices — the claim unit (D-01), the traces-back test
(D-05), the verdict vocabulary (D-13), the aggregate cut (D-16), and whether the per-document coding
table is published — were put to a blocking decision checkpoint before this text was written. The
checkpoint selected **option A-recommended: adopt all five as specified, with no deviation.** The
disclosed costs of that choice are stated inline in the sections below, exactly as the checkpoint
required.

## Purpose and scope

This protocol governs the per-document coding of every codeable document in the real corpus, the
re-coded control arm, and the aggregate verdict that turns per-document codings into a rate. **The
same instrument runs on both corpora.** A rule amended between the control coding and the real coding
would void the comparison — that is the mismatched-comparison error that produced the withdrawn
usage-asymmetry finding on 2026-07-24, and it is why every rule below is fixed here, once, before
either coding starts.

## What this protocol anchors on

The role locations this protocol codes against are the ones already recorded per document under the
section-role-based anchoring published in `docs/v8.12-section-census-findings.md`. This protocol
joins against those recorded rows and re-locates no role — re-locating would break instrument
consistency between the census phase and this coding phase.

The frozen harness `scripts/check-quality-harness.py` is read here as a specification and is never
invoked as the coding instrument. Its section slicer requires all six numbered template headings to
resolve in ascending order with no gaps, and it raises on most of the real corpus by construction —
which is exactly what forces a hand-supervised helper for this phase and what makes the re-coded
control arm (below) necessary rather than merely tidy.

**The real corpus** is the 13 documents of the local-only working set, referred to in every tracked

**Denominator rule.** Every rate uses the **11-document denominator fixed by Phase 178**, cited and
not re-derived. The two triaged-out follow-up-dispatch documents sit below the line and influence no
figure.

## Section-body boundary (D-02)

A role-located section's body runs from its heading to the next heading at the **same census level
or shallower**, or to end of file. The census level is the value already recorded per document by
Phase 179 and is not re-derived here. This binds both the Conclusion section and the Derivation
Chains section identically, so no new judgment enters on either side.

This is the frozen detector's own section-6 boundary rule with the fixed position swapped for the
role-located heading, so no new judgment enters relative to the code being transcribed.

**Two rejected variants, and why.** Heading-to-EOF was rejected: a trailing inserted section would
silently enlarge the denominator, and unlike the detector this variant has no appendix cut-off.
Heading-to-EOF-minus-tagged-insertions was rejected: it would make Phase 179's structural category
tags become load-bearing on a rate, when they were assigned to describe structure, not to gate one.

The reason token `SECTION-BOUNDARY-EOF` is fixed for the case where a body genuinely runs to end of
file.

## Chain identifier vocabulary (D-05)

The Derivation Chains section body is searched for chain identifiers under exactly three label
families:

- a two-letter uppercase prefix followed by a hyphen and one or more digits (for example a
  `XX-1`-shaped label);
- the literal word `Chain` followed by whitespace and a letter-or-digit token;
- a bare uppercase letter with optional trailing digits (the `bare-letter` family).

Identifiers are located under exactly two shapes: a heading line whose text opens with the label
followed by a colon, em dash, en dash or hyphen; or a line opening with a bold span whose text opens
with the label at a word boundary.

**Bare-letter family guard — precision correction, binding.** A `bare-letter`-family label counts
only when the section body uses the bare-letter **shape** at least twice, counted across **all**
bare-shaped labels pooled together **regardless of which letter each one is** — this is a pooled
count over the shape, not a per-letter count. Concretely: one incidental bare-shaped bold lead-in
using one letter, plus one unrelated incidental bare-shaped lead-in using a **different** letter,
pools to a count of 2; the guard does **not** fire; and both are accepted as chain identifiers even
though neither individually recurred. The rule is deliberately written this way — "the section body
uses the bare-letter shape at least twice, pooled across letters" — and **not** "the document uses
it at least twice," which reads per-letter and is a different, stricter rule that the code does not
implement. The reason token `BARE-LABEL-FAMILY-GUARD` is fixed for every time the guard actually
fires (excludes a lone bare-shaped label because the pooled count sits below two).

Identifiers are deduplicated in document order. A chain block runs from one located identifier to
the next, with the whole section body being a single block when no identifier is located.

## Claim unit (D-01)

The frozen detector's `_conclusion_claims` rule is transcribed to prose here, faithfully, including
the narrowness of exclusion (c), operating per physical line of the role-located Conclusion section
body after stripping surrounding whitespace.

**Two claim shapes, fixed:**

- **`bold-leadin`** — the stripped line opens with two asterisks, the bold span contains no further
  asterisk and no newline, and the span's final character before the closing asterisks is a colon;
  the claim text is the whole stripped line.
- **`list-item`** — the stripped line opens with either a decimal number followed by a period or a
  closing parenthesis, or a single hyphen or asterisk, then whitespace, then the remainder; the claim
  text is that remainder, stripped, without the marker.

A line matching the `bold-leadin` shape is never also considered as a `list-item`.

**Assertiveness test — precision correction, binding.** The candidate text is assertive when it ends
in a period, exclamation mark or question mark, followed by zero or more characters drawn from
exactly this five-character set: a straight single quote, a straight double quote, a closing round
parenthesis, a right curly double quote, and a right curly single quote — **or** when its stripped
length exceeds **40** characters (the literal threshold; it exists to keep bare short labels out of
the claim set). The permitted trailing-character set is exactly those five characters and no others.
It contains **no square bracket** and **no curly brace**. Write the set out precisely as above; do
not describe it loosely as "closing quotes or brackets" — that reading is not what the code
implements, and this protocol fixes the narrower, exact reading as the one being applied.

**Laxer citation-presence test**, used by both exclusions below: text carries a citation when it
contains any stored chain identifier as an exact case-sensitive substring, **or** contains any
normalized chain identifier that passes the loose-match safety test (below), **or** contains any
`GT-` identifier at all.

**Exclusion (b), token `b-label`.** A `bold-leadin` whose bold span ends exactly at the end of the
stripped line — nothing whatever follows the closing asterisks — and which carries no citation under
the laxer test is excluded as a pure section-intro label.

**Exclusion (c), all three conditions required.** The candidate carries no citation under the laxer
test; **and** the candidate matches one of exactly two shapes — a bold colon lead-in whose bold text
opens case-insensitively with one of these five lead-in phrases: `bottom line`, `in short`,
`in summary`, `to summarize`, `overall` (token `c-restatement`); or a line opening with a bold span,
an optional comma, the word `and`, a second bold span, and a colon (token `c-corollary`); **and** an
already-accepted earlier claim in the same section body can actually be located that itself carries a
citation under the laxer test. All three conditions are required, and the already-cited antecedent
must be **found**, never **assumed**.

**Anti-overreach guard (HONESTY-NOT-SCORE), stated on the page.** A genuinely-uncited imperative
recommendation that is neither shape (b) nor shape (c) remains counted and remains untraced. The rule
is transcribed to preserve that residual, not to tune a tally toward zero.

**Under-exclusion, logged, token `CLAUSE-C-SHAPE-MISS`.** A candidate that reads as a restatement but
matches neither clause-(c) shape is **not** excluded — it is counted, and logged with the reason token
`CLAUSE-C-SHAPE-MISS`. This under-exclusion pushes the figure **upward**, the direction this milestone
would be accused of wanting, which is precisely why every instance is logged and the count is
published beside the rate.

**Clause-(c) logging requirement, token `CLAUSE-C-APPLIED` (D-03).** Every clause-(c) application is
logged per document with the position of the earlier cited claim it restates and a structural reason
from the closed reason-token vocabulary below, so a later reader disagrees with one specific numbered
call rather than with the whole coding.

`scripts/check-quality-harness.py`'s `_selftest_limitation3_extractionscope` is the worked-fixture
reference for every boundary above; its fixtures are synthetic and contain no client content.

## Traces-back test (D-05)

A claim traces iff:

- **(i)** its text contains a chain identifier of the role-located Derivation Chains section, matched
  either as an exact case-sensitive substring of the stored form, or — after stripping a leading
  `Chain ` or `chain ` token and case-folding — as a substring of the case-folded claim, where that
  normalized form is at least **two characters long** and contains **at least one digit** (the
  loose-match safety test); **or**
- **(ii)** its text names two or more distinct `GT-` identifiers, with any trailing question mark
  stripped, that also appear together inside a single chain block.

Accepted citation forms: a bare parenthesized label, a bolded label following the word `chain`, and a
pluralized multi-identifier citation.

**Loose-match safety test, token `LOOSE-MATCH-UNSAFE`.** An identifier whose normalized form fails
the two-character-plus-digit safety test never loose-matches; the reason token `LOOSE-MATCH-UNSAFE` is
fixed for this case. Reason, stated on the page: a bare letter appears in nearly every English
sentence, and a bare digit matches inside any other number.

**Clause-(ii) trace, token `GT-COOCCURRENCE-TRACE`.** A claim that traces only under clause (ii) is
logged with the reason token `GT-COOCCURRENCE-TRACE`.

The test is purely presence or absence of a citation and never a judgment about whether the reasoning
is good — substantive derivability is correctness, which is out of scope and has had no instrument
since v8.10 and v8.11.

## Identifier equality and character basis

Stated unambiguously in one place: exact matching is case-sensitive substring matching of the stored
form; normalized matching is case-folded substring matching of the leading-`Chain `-stripped form,
gated by the two-character-plus-digit safety test; a `GT-` identifier matches on its digits with any
trailing question mark stripped. The character basis throughout is decoded Unicode code points — the
same unit the Phase 178 working-set manifest counts in — never bytes.

## Verdict vocabulary (D-13, D-04, D-06)

Exactly three per-document verdict values are permitted:

- **`UNTRACED`** — the document carries at least one untraced claim.
- **`TRACED`** — every claim in the document traces.
- **`NOT-CODEABLE`** — the D-04 disposition for a document Phase 179 tiered ROLE-ABSENT. This
  document stays visibly in the 11-document accounting with the disposition token
  `NOT-CODEABLE-ROLE-ABSENT`, and is excluded from the untraced numerator — counted neither
  `UNTRACED` nor vacuously `TRACED`.

This is exactly the frozen detector's per-document untraced-flag semantics, which is what makes the
real figure and the historical harness figure the same kind of number. **No fourth value exists.**
`PARTIAL` was considered and rejected: it is not the flag's shape, its boundary is one more judgment
surface, and the per-claim detail it would express is already carried by the secondary claim-level
rollup.

**D-06 sub-disposition, token `NO-ID-VOCABULARY`.** A document whose role-located Derivation Chains
section body yields zero chain identifiers under all three families **and** contains no `GT-`
identifier anywhere codes `UNTRACED`, stays in the numerator, and carries the sub-disposition
`NO-ID-VOCABULARY`, reported as its own count beside the rate — so a reader can see how much
incidence rests on absent id conventions rather than on claims skipping conventions that are present.
Rejected alternatives: widening the citation rule to accept prose or positional back-references
(replaces a mechanical test with a reading judgment and breaks comparability in the flattering
direction), and coding such documents `NOT-CODEABLE` (risks emptying the numerator if the id
convention is rare in real work).

**Empty-conclusion case, token `VACUOUS-TRACED`.** A role-located Conclusion section body that yields
zero claims under the claim-shape rule codes `TRACED`, consistent with the flag's own semantics, and
is flagged `VACUOUS-TRACED` and reported as its own count beside the rate — so no reader mistakes a
vacuous confirmation for a substantive one, the same discipline Phase 179 applied to its vacuous
relative-order contribution.

## Closed reason-token vocabulary (D-18, D-03)

Exactly these twelve tokens are published, each with a one-line definition. They may be extended only
by a recorded dated amendment, never silently mid-coding.

| Token | Definition |
|---|---|
| `NO-ID-VOCABULARY` | The Derivation Chains section body carries zero chain identifiers under all three families and no `GT-` identifier at all; the document still codes `UNTRACED`. |
| `VACUOUS-TRACED` | The Conclusion section body yields zero claims; the document codes `TRACED` vacuously. |
| `CLAUSE-C-APPLIED` | A claim was excluded under exclusion (c), logged with the position of the earlier cited claim it restates. |
| `CLAUSE-C-SHAPE-MISS` | A candidate reads as a restatement but matches neither clause-(c) shape, so it stays counted and untraced. |
| `SECTION-BOUNDARY-EOF` | A role-located section body genuinely runs to end of file. |
| `MERGED-ROLE` | Two governing roles resolve to the same located heading position (inherited from the census's `merged-role` finding). |
| `BARE-LABEL-FAMILY-GUARD` | A bare-letter-shaped label was excluded because the pooled bare-letter-shape count across the section body was below two. |
| `LOOSE-MATCH-UNSAFE` | A normalized chain identifier failed the two-character-plus-digit safety test and was not loose-matched. |
| `GT-COOCCURRENCE-TRACE` | A claim traced only under the two-or-more co-occurring `GT-` identifier clause. |
| `RULE-DID-NOT-DECIDE` | The pre-registered rule failed to decide a document cleanly; the case is recorded as evidence, not smoothed. |
| `NOT-CODEABLE-ROLE-ABSENT` | The D-04 disposition for a document Phase 179 tiered ROLE-ABSENT. |
| `OTHER-LOGGED` | A divergence that does not fit any other token; fuller structural detail is kept in the working set only. |

The vocabulary exists so that a divergence can be recorded in a public artifact without any client
content, and so that a divergence which does not fit a named token is recorded as `OTHER-LOGGED` with
fuller structural detail in the working set, rather than silently omitted.

**D-18's mandate, stated on the page.** Any ambiguity or judgment call encountered while coding is
recorded rather than smoothed — **including cases where the pre-registered rule turned out not to
decide a document cleanly**, token `RULE-DID-NOT-DECIDE`. The v8.10 and v8.11 lesson is that a
reading fork is itself the finding, and a rule that fails to decide is evidence, not an error to paper
over.

## Statistics, precision contract and the aggregate rule (D-14, D-16, D-17)

Defined over the real corpus:

- `n11` — the 11 in-denominator documents.
- `c` — the codeable subset: the in-denominator documents not coded `NOT-CODEABLE`.
- `u` — the count of codeable documents coded `UNTRACED`.

**Precision contract.** Every rate is reported as its raw integer pair. A decimal or percentage is a
derived convenience at most one decimal place using **round-half-to-even**, and is never stated
without its integer pair alongside it. No clause of the aggregate rule below is ever evaluated on a
rounded value.

**Headline (D-14).** Document incidence over codeable documents, always stated alongside the same
count over 11 (`n11`), with the claim-level rollup — untraced claims over total claims — pre-
registered as a **secondary** and never as the headline. Rejected alternatives: a claim-level
headline (no counterpart in the historical figure, and pooling lets one long conclusion section
dominate) and two co-headlines (invites a later reader to quote whichever suits).

**Aggregate cut (D-16).** Integer cuts on `u`:

- `u = 0` → **`ABSENT`** — the untraced-conclusions defect does not appear in real work output,
  recorded as measured and a **complete** result.
- `u >= 1` → **`PRESENT`**, with the incidence stated as the D-14 pair above.

**The boundary, stated explicitly:**

- `u = 0` → `ABSENT`
- `u = 1` → `PRESENT` (at the cut)
- `u = 2` → `PRESENT` (one step above the cut)

Both branches are complete results; neither is phrased as the phase succeeding and the other as the
phase failing.

**Per-project breakdown (D-15), pre-registered now.** The count of documents coded `UNTRACED` per
label, reported alongside the aggregate. The honest reading is fixed now: at cells of this size, no
per-project rate is meaningful, so the breakdown is published to show whether the finding concentrates
in one project's house style — never as a rate and never as an adjusted headline. The codeable
subset's per-label distribution is reported as measured rather than assumed to carry over from the
in-denominator distribution, and a label whose only in-denominator document is `NOT-CODEABLE` is shown
with a codeable cell of zero rather than omitted. This pre-registers the clustering disclosure Phase
179 publicly named as its own regret, at the only moment it is still fixable.

## What the control contributes (D-09, D-11, D-12)

The re-coded control arm reports its figure over **all 12** control documents **and**, separately,
over the **six-document post-fix subset**. The side-by-side comparison against the historical flat
6/6 uses the six-document subset, because that is the same documents on the same denominator, with the
12-document figure stated alongside.

**Historical figure's provenance, one sentence.** The flat 6/6 is the frozen mechanical detector's
per-document untraced flag over `tests/quality-baseline-v8.7-postfix/analyses/`, cited separately on
its own basis, and it is never recomputed by this phase.

**D-11, fixed before any figure exists.** If the re-coded control figure does not reproduce the
historical flat 6/6, both figures are published side by side, the delta is stated, and it is
**deliberately not reconciled** — a divergence is itself evidence about how much the defect's
incidence depends on the instrument, and pre-registering no-reconciliation now is what stops an
explanation being fitted after the figures exist. Rejected alternatives: a mismatch threshold that
invalidates the arm, and per-document reconciliation.

**D-12 attribution vocabulary**, fixed against the control's own untraced document count over its 12
documents:

- `0` → `REAL-USE-SPECIFIC`
- `1` → `INDETERMINATE`
- `2` or more → `PRE-EXISTING`

Attribution never changes the verdict — the verdict is decided on the real corpus alone, and the
control may not be used to launder or soften a real-corpus finding. The verdict statement is
incomplete unless the real corpus's and the control's figures appear side by side.

## Execution, instrument discipline and the digest lock (D-07, D-08)

Execution is a working-set-only helper plus recorded human judgment. The helper is a sibling of the
Phase 179 census helper in the same working-set directory; it is never placed under `scripts/`, never
wired into `scripts/check-firewall-battery.sh`, never added to the CI gate table in `CLAUDE.md`, never
counted in the 16/16, and is never given an assertion-harness mode flag — the hand-built fixtures it
is proven on are ordinary input directories, not a test harness.

The helper extracts the role-located Conclusion and Derivation Chains section bodies, applies the
claim-shape and citation rules mechanically, and emits per-claim rows as **structural facts only** —
position, shape token, assertiveness basis, citation present or absent, matched identifier form — and
**never claim text to any artifact**. The human resolves only the clause-(c) exclusions and the
flagged exceptions.

**The tool-versus-instrument line.** A helper outside git is a tool and is permitted; a script under
`scripts/`, a committed re-runnable command, a counter file, a CI gate or a matrix row is an
instrument and is barred.

**Digest lock, unchanged from Phase 179.** Build the helper, prove it on hand-built fixtures, record
its SHA-256 before the first real document is opened, and halt on mismatch.

**Digest limitation, restated rather than inherited silently.** The digest value and the assertion
that it was checked both live outside git, so no reader can confirm from this repository that the
instrument was unmodified between the two corpora. This matters more than the per-document limitation,
because the same-instrument property is the entire premise the control arm exists to protect.

## Blindness boundary

This is the phase where blindness to conclusion content necessarily ends. Its bounds are fixed: the
pre-registration is authored and committed before any document is opened; the helper renders no claim
text to any artifact; on-screen exposure during exception resolution is bounded to the single claim
under adjudication and is logged; and no client content, proper noun, verbatim quote or distinctive
figure enters any tracked file, plan, summary or commit message. Phase 179 established and published
that no conclusion body text was read anywhere in that phase, on either corpus, which is what makes
this pre-registration genuinely blind.

## Privacy rule

No verbatim claim text and no verbatim heading text from either corpus enters any artifact — not the
tracked findings document, not the working-set coding record, not a commit message, not a plan
summary. Real-corpus documents are named by label plus chronological index; control documents are
named by baseline filename. The per-document coding table published in the tracked findings carries
only structural cells and reason tokens from the closed vocabulary above.

## What this protocol does not assert

At commit time no coding exists, no claim count exists, no untraced count exists, no rate exists and
no verdict exists. This document records rules only. It makes no judgment about whether any analysis's
reasoning is correct — correctness has no instrument, v8.10 designed one and v8.11 closed it, and this
phase codes traceability structure, not accuracy. It fixes no defect: byte-freeze holds and a fix
needs its own trigger and its own milestone.
