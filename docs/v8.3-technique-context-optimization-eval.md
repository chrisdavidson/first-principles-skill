## Methodology

This is v8.3's fourth exercise of the v8.0 closure clause "any future work is a fresh project
decision" (following v8.1 external-review triage, and v8.2's re-investigation of v8.1's 19
not-approved items). Where v8.1/v8.2 evaluated *external* recommendations, v8.3 turns the same
evidence-grounded, honesty-not-score discipline inward — onto the agent's own 8-technique
portfolio and its assembled context weight. The governing decisions, carried verbatim in intent
from [`148-CONTEXT.md`](../.planning/phases/148-deep-evaluation-optimization-plan/148-CONTEXT.md):

- **D-01 — Structured 4-dimension overlap rubric, cross-checked against live evidence.**
  "Genuine overlap" between two techniques is decided by scoring four dimensions — (a) inputs
  it needs, (b) outputs it produces, (c) failure-mode/blind-spot it catches, (d) when it fires
  (Step 0 trigger + phase placement) — and calling an overlap "genuine" (merge-worthy) only when
  those dimensions substantially collapse. Every candidate verdict is THEN cross-checked against
  the v7.4 live 9-technique Step 0 re-baseline's per-row K/N data
  ([`expansion-measurement-verdict.md`](expansion-measurement-verdict.md)) — which techniques
  empirically added zero result breadth — so no merge/no-merge judgment rests on prose assertion
  alone. The four named candidate pairs (pre-mortem↔inversion, fishbone↔five-whys,
  estimate↔theoretical-limit, second-order↔pre-mortem) are explicitly tested, and the mapping is
  free to surface additional pairs beyond those four — the four are a floor, not a ceiling, on
  what gets tested.
- **D-02 — Body weight measured two ways, both reported.** Context weight is accounted (1) as the
  assembled ~598/644-line agent body, per-section / per-technique (the literal BODY-01 reading,
  and the figure the 644-line pre-commit body-budget gate enforces), AND (2) as the full
  per-technique **fire cost** = assembled-body inline + the on-demand `shared/references/<slug>.md`
  file that loads when the technique actually runs + its worked example(s). The fire-cost view is
  the headline because it is expected to surface the real heavy hitters the assembled-body view
  hides — the reference files carry far more weight per technique (five-whys 234 / theoretical-limit
  204 / estimate 194 / fishbone 188 lines) than their compact inlined procedures do.
- **D-03 — Balanced recommendation posture, with a flagged bold sketch.** §5/§6 rank ALL
  candidate optimizations (behavior-preserving slims, technique merges, reference/example
  extraction to on-demand loading) AND separately author a full pull-when-needed
  alternative-architecture sketch as an explicitly-flagged future-milestone option — not the sole
  headline. Because v8.3 is analysis-only and every recommendation is byte-freeze-costed, boldness
  costs nothing: the sketch is a costed finding, not a commitment. The architecture assessment
  must anchor to the plugin's existing 13 focused-mode slash skills as the pull-when-needed
  pattern already in production, not a greenfield proposal.
- **D-04 — 4-factor composite prioritization.** §6's PLAN-01 items are ranked by
  context-savings × goal-fidelity-risk × byte-freeze-cost × implementation-effort, mirroring the
  v7.10 agent-goal-alignment audit's severity × leverage × offline-fixability composite
  (`docs/agent-goal-alignment-audit.md` precedent). Each factor is scored on a small explicit
  scale; every item names its byte-freeze relaxation cost and the live re-measure it would force.
- **D-05 — Fidelity is a named forward test, never an assumed-safe claim.** "Preserves the same
  analytical goals" cannot be live-measured this milestone (offline-only, no `claude` spend
  authorized). For every merge/slim/architecture recommendation, the evaluation states the
  *specific* live re-measure a future milestone must run to confirm goal-fidelity (a Step 0
  re-baseline for a technique-count change; a routing re-measure for a trigger change) —
  honesty-not-score (D-01 global) applied to this milestone's own forward-looking claims, not just
  its backward-looking evidence.

### Scope & Invariants

**ANALYSIS-ONLY.** This document is the sole write of the v8.3 milestone. No change lands in
`shared/` or the generated `first-principles/` tree; no technique merge, body edit, or
architecture change is applied — every finding is recommended and costed, never executed.

**Byte-freeze is a HARD constraint, not a debate.** The following stay byte-unchanged throughout
this document and this milestone:

- Detector marker counts: pre-mortem **9**, fishbone **7**, inversion **13**, trade-off **10**.
- `MIN_HEADER_HITS == 2`.
- `_COMPOSER_FOCUS_CEILING == 4`.
- The v7.8 guard column + stay-in-composer tiebreaker (Step 0 negative-match guard, `shared/spine/SKILL-body.md`).
- All frozen baselines/captures v5.0–v7.13 (`tests/step0-baseline-*.md`, `tests/step0-captures-*/`).
- The agent body (`shared/spine/SKILL-body.md`, `first-principles/agents/first-principles.md`) —
  byte-identical at 598/644 lines throughout this evaluation.

Any recommendation this document makes that WOULD require relaxing one of the above is recorded
as a **costed finding for a future milestone decision** — the v8.2/GROK-15 byte-freeze-cost
pattern. This document never relaxes byte-freeze and never forms a standing opinion on whether it
*should* persist; that question is out of scope (148-CONTEXT.md D-08 lineage).

**OFFLINE-ONLY.** No task in this milestone invokes `claude -p` or any live routing/Step 0 run.
Evidence is the repo itself (agent body, `shared/spine/`, `shared/references/`, `shared/examples/`)
plus three prior verdict documents already committed: `expansion-measurement-verdict.md` (v7.4),
`decompose-five-whys-merge.md` (v7.5), and `merge-validation-verdict.md` (v7.6).
