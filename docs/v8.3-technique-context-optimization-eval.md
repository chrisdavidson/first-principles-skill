## Methodology

This is v8.3's fourth exercise of the v8.0 closure clause "any future work is a fresh project
decision" (following v8.1 external-review triage, and v8.2's re-investigation of v8.1's 19
not-approved items). Where v8.1/v8.2 evaluated *external* recommendations, v8.3 turns the same
evidence-grounded, honesty-not-score discipline inward — onto the agent's own 8-technique
portfolio and its assembled context weight. The governing decisions, carried verbatim in intent
from [`148-CONTEXT.md`](../.planning/phases/148-deep-evaluation-optimization-plan/148-CONTEXT.md):

- **D-01 — Structured 4-dimension overlap rubric, cross-checked against live evidence.**
  "Genuine overlap" between two techniques is decided by scoring four dimensions — (a) inputs
  it needs, (b) outputs it produces, (c) failure-mode/blind-spot it catches, (d) when it fires
  (Step 0 trigger + phase placement) — and calling an overlap "genuine" (merge-worthy) only when
  those dimensions substantially collapse. Every candidate verdict is THEN cross-checked against
  the v7.4 live 9-technique Step 0 re-baseline's per-row K/N data
  ([`expansion-measurement-verdict.md`](expansion-measurement-verdict.md)) — which techniques
  empirically added zero result breadth — so no merge/no-merge judgment rests on prose assertion
  alone. The four named candidate pairs (pre-mortem↔inversion, fishbone↔five-whys,
  estimate↔theoretical-limit, second-order↔pre-mortem) are explicitly tested, and the mapping is
  free to surface additional pairs beyond those four — the four are a floor, not a ceiling, on
  what gets tested.
- **D-02 — Body weight measured two ways, both reported.** Context weight is accounted (1) as the
  assembled ~598/644-line agent body, per-section / per-technique (the literal BODY-01 reading,
  and the figure the 644-line pre-commit body-budget gate enforces), AND (2) as the full
  per-technique **fire cost** = assembled-body inline + the on-demand `shared/references/<slug>.md`
  file that loads when the technique actually runs + its worked example(s). The fire-cost view is
  the headline because it is expected to surface the real heavy hitters the assembled-body view
  hides — the reference files carry far more weight per technique (five-whys 234 / theoretical-limit
  204 / estimate 194 / fishbone 188 lines) than their compact inlined procedures do.
- **D-03 — Balanced recommendation posture, with a flagged bold sketch.** §5/§6 rank ALL
  candidate optimizations (behavior-preserving slims, technique merges, reference/example
  extraction to on-demand loading) AND separately author a full pull-when-needed
  alternative-architecture sketch as an explicitly-flagged future-milestone option — not the sole
  headline. Because v8.3 is analysis-only and every recommendation is byte-freeze-costed, boldness
  costs nothing: the sketch is a costed finding, not a commitment. The architecture assessment
  must anchor to the plugin's existing 13 focused-mode slash skills as the pull-when-needed
  pattern already in production, not a greenfield proposal.
- **D-04 — 4-factor composite prioritization.** §6's PLAN-01 items are ranked by
  context-savings × goal-fidelity-risk × byte-freeze-cost × implementation-effort, mirroring the
  v7.10 agent-goal-alignment audit's severity × leverage × offline-fixability composite
  (`docs/agent-goal-alignment-audit.md` precedent). Each factor is scored on a small explicit
  scale; every item names its byte-freeze relaxation cost and the live re-measure it would force.
- **D-05 — Fidelity is a named forward test, never an assumed-safe claim.** "Preserves the same
  analytical goals" cannot be live-measured this milestone (offline-only, no `claude` spend
  authorized). For every merge/slim/architecture recommendation, the evaluation states the
  *specific* live re-measure a future milestone must run to confirm goal-fidelity (a Step 0
  re-baseline for a technique-count change; a routing re-measure for a trigger change) —
  honesty-not-score (D-01 global) applied to this milestone's own forward-looking claims, not just
  its backward-looking evidence.

## §1 Technique Overlap Map (OVERLAP-01)

### Collapse scale

Each of the four D-01 dimensions is scored **0–2** for a candidate pair:

| Score | Meaning |
|-------|---------|
| **0** | The dimension is clearly distinct between the two techniques — different object class, artifact shape, blind spot, or firing mechanism, usually because at least one of the two reference docs explicitly names the other as its differentiator or complement. |
| **1** | Partial / adjacent overlap — the two techniques share surface vocabulary, a neighbouring phase, or an adjacent object class, but the underlying mechanism still diverges. |
| **2** | Substantial collapse — the dimension is functionally the same job under a different name. |

Summed across the four dimensions a pair scores **0–8**. This document calls a pair **genuine
overlap (merge-worthy)** only when the total is **≥5 AND at least two of the four dimensions score
2** — i.e. the pair must collapse on more than one axis, not just accumulate partial credit on
all four. A pair that scores moderately (≥5) without two dimension-2 hits is recorded as
**PARTIAL overlap** — a real signal worth carrying into §2/§6, but not itself a merge case.

### Candidate-pair verdicts

Each verdict states the 4-dimension score (`a/b/c/d`, each 0–2) and the total, then cross-checks
against the relevant v7.4 live S-P row(s) from
[`expansion-measurement-verdict.md`](expansion-measurement-verdict.md).

#### pre-mortem ↔ inversion

**Score: a=0, b=1, c=1, d=0 → total 2/8, 0 dimensions at 2.**

- **(a) Inputs — 0.** Distinct object classes by the reference docs' own explicit rule:
  `inversion.md` states "inversion stress-tests a **claim**; pre-mortem stress-tests a **plan**"
  and names pre-mortem as the tool to use when "a concrete plan with actions and a timeline
  exists."
- **(b) Outputs — 1.** Both produce failure-oriented findings, but pre-mortem's output is an
  unstructured, raw failure-cause list while inversion carries a formal 4-header output contract
  — different artifact shape, same general "list of what could go wrong" family.
- **(c) Failure-mode — 1.** Both look backward from a failure state, but pre-mortem catches a
  *plan's* structural weaknesses (optimism bias) while inversion catches a *claim's* silent
  unverified preconditions — related direction, different object.
- **(d) When it fires — 0.** Different Step 0 trigger vocabulary (no shared phrase), different
  phase placement (pre-mortem = Phase 5 Validate with guard-phrase suppression; inversion =
  Phase 2 Challenge Assumptions, no guards).

**v7.4 cross-check:** pre-mortem S-P01 **3/5 PASS**; inversion S-P02 **1/5 FAIL** (RR-114-01,
still CARRIED 1/5 at the v7.13 live re-measure per `docs/v8.0-final-closure.md`). The two
techniques do not share a routing-failure pattern — one passes reliably, the other has been a
persistent, accepted-final residual across three re-baselines. No shared-failure signal to
support a merge.

**Verdict: NOT genuine overlap.** The structural score (2/8) and the diverging live pass rates
both point the same direction — pre-mortem and inversion are correctly kept as distinct
techniques operating on distinct object classes (plan vs. claim).

#### fishbone ↔ five-whys

**Score: a=1, b=0, c=0, d=1 → total 2/8, 0 dimensions at 2.**

- **(a) Inputs — 1.** Adjacent object classes — fishbone needs a multi-cause **effect**, five-whys
  causal mode needs a single-chain **symptom** — but `fishbone.md`'s own "Not a good fit" section
  explicitly names five-whys as the depth-first alternative "if the problem has a single traceable
  causal chain," making breadth-vs-depth the documented differentiator, not a shared input class.
- **(b) Outputs — 0.** Fishbone produces a category-organised tree of candidate causes; five-whys
  produces either a single-chain root cause + corrective action, or a set of verified GT-N
  primitives. Structurally different shapes (tree-across-categories vs. linear-chain-to-anchor).
- **(c) Failure-mode — 0.** Fishbone catches an overlooked *category* of cause (breadth blind
  spot); five-whys catches a surface fix that leaves the *root* untouched, or an unverified claim
  constituent (depth blind spot). Both reference docs' own Handoff sections describe the pair as
  **complementary**, not duplicative: "fishbone first to survey the cause space, then 5-Whys to
  drill the highest-priority branch."
- **(d) When it fires — 1.** Adjacent phase placement (fishbone = Phase 2; five-whys
  reduce-to-primitives = the canonical Phase 3 tool, with causal mode also reachable from Phase 2)
  but no shared Step 0 trigger phrase.

**v7.4 cross-check:** fishbone S-P03 **3/5 PASS**; five-whys S-P04 **4/5 PASS** — both passing,
neither a routing failure. The v7.4-era technique that actually failed and was subsequently merged
was **`decompose`** (S-P09, **0/5 FAIL, clean**) — a *separate* skill at v7.4 that v7.5 absorbed
into five-whys' reduce-to-primitives mode (`decompose-five-whys-merge.md`). Fishbone was never the
decompose merge's counterpart; it passed cleanly at v7.4 and was never a merge candidate in prior
art.

**Verdict: NOT genuine overlap.** Both the structural score (2/8) and the live evidence confirm
fishbone and five-whys are complementary (breadth-then-depth), not duplicative. Prior art's actual
merge target for this input-class was `decompose`, already executed at v7.5 — this pair is
correctly distinguished from that closed action.

#### estimate ↔ theoretical-limit

**Score: a=1, b=1, c=2, d=1 → total 5/8, 1 dimension at 2.**

- **(a) Inputs — 1.** Different target objects (estimate: an uncertain quantity; theoretical-limit:
  a suspected-conventional figure) but both are quantitative/physical-law-grounded, and
  `theoretical-limit.md`'s own "Cross-technique continuity" section reuses the *same* worked
  example (molten-salt CSP, Solar Salt) and the *same* GT-N chain as estimate's worked example —
  the two docs are written as a connected pipeline on shared subject matter.
- **(b) Outputs — 1.** Both produce a "bracket," but with different semantics: estimate brackets
  *uncertainty around a magnitude* `[lower, central, upper]`; theoretical-limit brackets the *gap*
  between a derived ceiling and the conventional figure. `theoretical-limit.md`'s own Handoff
  section states this distinction explicitly ("estimate hands off a bracketed magnitude ...
  theoretical-limit hands off a law-permitted ceiling and a gap").
- **(c) Failure-mode — 2.** Genuinely the same underlying blind spot applied to different
  quantities: both guard against substituting an **external reference point** (a comparable past
  project; a best-in-class incumbent) for a **first-principles-derived value** — estimate's
  "Citing an analogy as a factor value" failure mode and theoretical-limit's "Citing best-in-class
  practice as the ceiling" failure mode are the same reasoning-by-analogy trap, just applied to a
  magnitude vs. a ceiling.
- **(d) When it fires — 1.** Same phase placement (both Phase 4, Reason Upward) but distinct,
  non-colliding Step 0 trigger vocabulary (confirmed no 4-gram collision by the live VAL-04 gate).

**v7.4 cross-check:** estimate S-P10 **0/5 FAIL (clean)**; theoretical-limit S-P14 **0/5
(spend-limit-indeterminate at v7.4, RR-108-05)**. Critically, both residuals were re-measured
cleanly at v7.13 and remain **ACCEPTED-FINAL, true K/N 0/5 for both**, per
`docs/v8.0-final-closure.md` §3 — the strongest shared-failure signal of any pair tested here: two
techniques that have *never once* fired live across two independent clean measurements (v7.4 and
v7.13), sharing the same underlying blind spot (dimension c=2) and the same phase placement.
However, v7.4's own Merge Recommendation did **not** pair these two — it named
`theoretical-limit`↔`inversion` as its SECOND candidate (on the *prior overlap analysis*, not
live evidence, since S-P14 was spend-limit-indeterminate at that time) and flagged `estimate` as
"partner needs scoping," explicitly warning not to pre-select a partner without live evidence.
This document's structural mapping, now run against clean v7.13 evidence unavailable at v7.4 time,
finds `estimate`↔`theoretical-limit` — not `theoretical-limit`↔`inversion` — is the pair with the
strongest combined structural + live-evidence case.

**Verdict: PARTIAL overlap (5/8, below the ≥2-dimensions-at-2 merge-worthy bar).** Inputs and
outputs remain genuinely distinct per each doc's own explicit differentiation — this is not a
full merge case. But the shared failure-mode-caught (c=2) plus the twin clean 0/5 CARRIED
live-routing failure is the single strongest empirical signal this map surfaces, and the strongest
BODY-02 slimming/consolidation candidate (both are among the four heaviest reference files: estimate
194 lines, theoretical-limit 204 lines). Carried into §2/§6 as a flagged finding, not a merge
recommendation: the twin 0/5 is plausibly a **Step 0 trigger-tuning problem** (both techniques
under-route regardless of what they overlap with), not necessarily evidence the analytical jobs
themselves should collapse — a distinction future re-measurement work should test before any merge
executes.

#### second-order ↔ pre-mortem

**Score: a=0, b=0, c=0, d=0 → total 0/8, 0 dimensions at 2.**

- **(a) Inputs — 0.** Different object classes and different reasoning direction: second-order
  needs a first-order **conclusion** already reached (forward direction — "if it holds, what
  follows?"); pre-mortem needs a **plan** about to be committed (backward, prospective-hindsight

- **(b) Outputs — 0.** Second-order produces consequence lists extending the Derivation Chain (or

- **(d) When it fires — 0.** Second-order runs **mandatorily** at the Phase 4→5 boundary in

  merely distinct triggers.

**v7.4 cross-check:** second-order S-P06 **5/5 PASS** — the single strongest passer in the entire
9-technique v7.4 matrix; pre-mortem S-P01 **3/5 PASS**. Both pass, at markedly different rates,

**Verdict: NOT genuine overlap — the weakest of the four named pairs (0/8).** `second-order.md`'s
