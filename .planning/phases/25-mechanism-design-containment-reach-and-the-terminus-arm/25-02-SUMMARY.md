## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Arm 2's mutation crashed with `KeyError` instead of producing a clean `missing=` finding**
- **Found during:** Task 3, step 9 (the plan's own mandated mutation proof)
- **Issue:** Deleting the `docs/TESTING.md` entry from `_CONTAINMENT_SURFACES` (lock left intact, per the plan's Arm 2 instructions) crashed `cmd_check()` with `KeyError: 'docs/TESTING.md'` at `_surface_check_spelled_out[surface_key]`, because the loop looked up a named surface's `check_spelled_out` polarity in a dict derived from the table before deciding whether to add the surface to `reached` -- when the table no longer had that entry, the lookup itself raised before the roster floor ever got a chance to run.
- **Fix:** Reordered the loop so a named surface's table membership is checked BEFORE it is added to `reached`: if the surface key is not present in the table-derived `_surface_check_spelled_out` dict, the loop `continue`s without adding it to `reached` (rather than crashing), so a genuinely unregistered surface is correctly absent from `reached` and the roster floor reports it in `missing=` exactly like Arm 1's loop-level skip.
- **Files modified:** scripts/gen-gate-docs.py
- **Verification:** Re-ran both mutation arms after the fix on a fresh disposable `rsync --exclude .git` scratch copy: both now report the identical `containment-surface-roster: missing=['docs/TESTING.md'] extra=[]` finding with exit 1, plus the expected accompanying ledger-staleness findings. `git status --porcelain` on the real repository confirmed empty before the first mutation and after the last (in both the pre-fix and post-fix mutation runs).
- **Committed in:** `ed81ae1` (Task 3 commit)

**2. [Rule 1 - Bug] Missed a ledger entry in the first draft of the adjudicated dict**
