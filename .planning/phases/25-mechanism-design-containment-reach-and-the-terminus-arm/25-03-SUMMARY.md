# Phase 25 Plan 03: The chain-terminus arm and CR-01's correction Summary

**Built a value-continuity chain-terminus arm (`_delta_chain_hops` / `_link_delta_chains` / `chain_terminus_problems`) that reads a narrated `N → M → P` growth chain as one object rather than a sequence of independently-stripped delta vectors, wired it into `CONF-SURFACE`'s existing containment loop with a per-surface `fence-authoritative`/`fence-silent` corroboration policy, and corrected CR-01's stale `184` on `docs/gates/CONF-SURFACE.md` to the live `181` in the same commit so the widened check never lands red.**

## Accomplishments

- `_delta_chain_hops(text)` — extracts every delta-vector match (slash-paired, single-operand arrow, English-prose "to", plus a parser-only spelled-out extension of the English-prose form) from a page's outside text, in document order, as `(left_tuple, right_tuple, matched_span)` hops. Patterns are selected out of the live `_CITATION_SHAPE_RES` tuple by identity against named constants (`_ARROW_TRANSITION_PATTERN`, `_ENGLISH_PROSE_TRANSITION_PATTERN`, mirroring the existing `_SLASH_PAIRED_TRANSITION_PATTERN`) — no hand-copied regex text anywhere in the new code.
- `_link_delta_chains(hops)` — assembles maximal chains by value continuity (non-adjacent, document-order), returning only chains of two or more hops; this is D-03's growth-chain gate, falling QUAL-01's two flat single-hop pairs out of grammar with no special-casing.
- `chain_terminus_problems` / `_chain_terminus_surface_verdicts` — the three-outcome discriminator (stale / current / uncorroborable), driven by a `terminus_policy` field now on all four `_CONTAINMENT_SURFACES` entries: `fence-authoritative` for `docs/gates/*.md` (a stale terminus is a finding), `fence-silent` for the three narrative surfaces (an unmatched terminus is uncorroborable, not caught — a disclosed, measured bound). Reuses `detail_page_containment_problems`'s own flat whole-fence set-membership primitive; no per-format named-field lookup was built.
- Wired into `cmd_check()`'s existing containment loop with one `problems += chain_terminus_problems(...)` line beside the existing `detail_page_containment_problems` call.
- CR-01 corrected on `docs/gates/CONF-SURFACE.md`: the growth-chain paragraph now narrates the two further hops `_DEFERRED_LEDGER_MAX`'s own growth-history comment already records (`184 → 183` by plan 22-10 Task 1, `183 → 181` by plan 22-10 Task 2) — no existing figure deleted or hedged — plus a new numbered `(7)` disclosed bound publishing the uncorroborable outcome for a product reader.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `describe()` calling `generate_all()` caused unbounded subprocess recursion**
- **Found during:** Task 2, first `--check` run after wiring `_chain_terminus_live_tallies()` into `describe()`
- **Issue:** `_chain_terminus_live_tallies()`'s first draft called `generate_all()` to get each surface's rendered text. `generate_all()` calls `harvest(_gate_registry.ENTRIES)`, which runs every registered script — including `gen-gate-docs.py` itself — as a subprocess with `--describe`. Since `describe()` now called `generate_all()`, every self-harvest subprocess invocation of `gen-gate-docs.py --describe` re-triggered `generate_all()` → `harvest()` → a fresh self-harvest subprocess, recursing until the 120-second subprocess timeout fired. Confirmed by direct execution (`python3 scripts/gen-gate-docs.py --check` hung past 120s and the background task's traceback showed `subprocess.TimeoutExpired` inside `harvest()`), not discovered by reading code.
- **Fix:** Rewrote `_chain_terminus_live_tallies()` to read real on-disk text directly via `Path.read_text()` for all four surfaces (`CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/TESTING.md`, and each `docs/gates/*.md` page resolved via `_gate_registry.ENTRIES`/`_page_slug`), never calling `generate_all()` — mirroring `run_literal_scan()`'s own pre-existing discipline of reading real files for exactly this reason.
- **Files modified:** scripts/gen-gate-docs.py
- **Verification:** `python3 scripts/gen-gate-docs.py --describe` and `--check` both complete in well under the timeout after the fix, `chain_termini_stale`/`_current`/`_uncorroborable` populate correctly, and `--self-test`'s existing controls (which already exercise `describe()` via `_control_describe_emits_parseable_json`) still pass.
- **Committed in:** `7a1ede1` (Task 2 commit; caught and fixed before any commit was made with the bug present)

**2. [Rule 1 - Bug] Two CONF-13 count-noun-adjacency trips in this plan's own new prose**
- **Found during:** Task 1 (`_link_delta_chains`'s docstring) and Task 2 (the CR-01 correction paragraph)
- **Issue:** (a) `_link_delta_chains`'s disclosed-bound docstring first read "measured zero occurrences across all 34 surfaces at plan time" — "34" sits within 3 tokens of the noun "surfaces" (in CONF-13's `_LITERAL_NOUNS` vocabulary), tripping the self-file docstring ratchet. (b) The CR-01 correction's first draft read "...introduced a new digit literal: Task 1 lowered it 184 → 183..." — the noun "literal" fell within the scanner's 3-token adjacency window of the number "1" in "Task 1", producing a live `docs/gates/CONF-SURFACE.md:226: hand-maintained count literal 'literal: Task 1'` finding on `--check`.
- **Fix:** (a) Reworded to "across the whole tree-wide surface population examined at plan time" (no digit adjacent to "surfaces"). (b) Restructured the paragraph so "Task 1"/"Task 2" each open their own clause, pushing "digit"/"literal" mentions outside the 3-token window of any adjacent number — verified directly against the real `_scan_text_for_literal_hits`/`--check` before considering either fix final, not by re-reading the prose and guessing.
- **Files modified:** scripts/gen-gate-docs.py, docs/gates/CONF-SURFACE.md
- **Verification:** `python3 scripts/gen-gate-docs.py --self-test` and `--check` both green after each fix; `--check`'s CONF-13 finding disappeared with the second fix specifically (confirmed by re-running `--check` before and after the reword).
- **Committed in:** `1155cdf` (fix (a)) and `7a1ede1` (fix (b)); neither was ever committed in its broken form.
