## Decisions Made

- **Section title wording (deviation from the plan's literal example text).** The plan's `<action>` text gave `## REACH-or-LEVEL determinations (v9.1.0, CONTAIN-01/02/03)` as the exact title. Before writing it to disk, I tested it directly against the live `detail_page_containment_problems()` function (per this repo's "verify by mutation, not by reading" discipline) and found the slash-compound `CONTAIN-01/02/03` leaves a residual bare `'03'` outside the generated fence with no fence counterpart -- a genuine containment failure, not a hypothetical one (confirmed: `["containment: docs/gates/CONF-SURFACE.md states '03' outside a generated fence with no matching literal inside one (D-06)"]`). I used the comma-separated form `CONTAIN-01, CONTAIN-02, CONTAIN-03` instead, verified clean (`[]`) against the same function before committing. This is a Rule 1 (bug) auto-fix: the plan's example text, if transcribed literally, would have broken its own acceptance criterion (`--check` exits 0).
- **Named module constant over a same-file retype.** `_SLASH_PAIRED_TRANSITION_PATTERN` is defined once, immediately above `_CITATION_SHAPE_RES`, and referenced both in the tuple's `re.compile(...)` call and in the two same-file self-test controls that need the exact string (the containment-strip control uses it implicitly via the compiled pattern already in the tuple; the ordering control references it directly by name). `scripts/census-delta-vectors.py`'s own `_EXPECTED_SLASH_PATTERN` is a deliberate, separate hardcoded retype of the identical text -- consistent with how `_EXPECTED_ARROW_PATTERN`/`_EXPECTED_ENGLISH_PATTERN` already work there: the whole point of that cross-file constant is to assert by string equality that the live pattern in `gen-gate-docs.py` still matches what the census tool expects, so importing it there would defeat its own purpose.
