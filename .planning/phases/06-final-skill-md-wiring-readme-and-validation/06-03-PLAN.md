    (Pitfall 5: do one cross-reference read against SKILL.md after drafting).

    `first-principles-thinking/references/pre-mortem.md`,
    `first-principles-thinking/references/trade-off-analysis.md`. A named list, not
    a duplicate of the SKILL.md blurbs.

    (5) A "Worked examples" H2 section — the four examples by domain (software/
    systems, product/business, personal/general, science/engineering), one sentence
    each on the scenario, linking `first-principles-thinking/examples/software-systems.md`,
    `product-business.md`, `personal-general.md`, `science-engineering.md`.

    the four domain-spread worked examples, and the sharpened 5-phase methodology

    Note that the symlink mode keeps the cloned repo as the live source of truth

    shell commands (pattern in 06-PATTERNS.md installation section). The section
    MUST explicitly call out the correctness requirement that the installed
    directory be named `first-principles-thinking` — it must equal the frontmatter
    `name`, and the skill lives in a `first-principles-thinking/` subdirectory of
    this repo.

    End the README after Installation. Do NOT add a contributing or dev-tooling
    section — `skills-ref`/`markdownlint`/dev workflow stay in CLAUDE.md (D-11).
    All internal links use forward slashes. Use H2 for top-level sections, H3 only
    if a section needs sub-topics, `bash` language on every shell code fence. No
    `---` section dividers (standard GitHub README convention omits them).
