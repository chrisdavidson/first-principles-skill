    3. `## When to reach for this` — the use case: two or more options are genuinely viable (none obviously dominant), the choice spans multiple criteria that pull in different directions, and a single intuitive pick would be hard to justify to others.
    4. `## Procedure` — follow the canonical Weights-Lock numbered procedure in 04-RESEARCH.md lines ~504-518. As a numbered list: (1) Name the options being compared. (2) List criteria — 5-8 that matter; lock the list, no new criteria after this step. (3) Assign weights and LOCK them now — give each criterion a relative weight (e.g. 1-5); the word "lock" or "finalize" must appear at this step; lock weights before scoring any option; note that if you cannot assign weights without first looking at how options score, you are not ready to use this tool. (4) Score each option on each criterion independently. (5) Compute weighted scores — weight x score per criterion, summed per option. (6) Read the result — the highest score is the analysis's recommendation, not an automatic decision; if it surprises you, re-examine the weights, but only if you can state why a weight was wrong before seeing the result. The lock-weights-before-scoring step (step 3, before step 4 scoring) is the core discipline and must be a discrete, ordered step (SC-3). Include the sensitivity check — if two options score within roughly 10% of each other, do not refine scores; instead identify the single criterion whose weight, if changed, would flip the result — placed either at the end of the procedure or as a note after step 6.
    5. `## Example` — a mini-example in the everyday/non-technical domain (D-04). Must NOT use any of the four Phase 5 worked-example domains (software / product / personal / science). Show a compact weighted matrix table — options as rows, criteria as columns, with a weight row and score rows; keep to 3 options x 4-5 criteria maximum to stay within the line budget. Walk through the weighted-score computation and the resulting recommendation.
    6. `## Failure modes` — surface the failure modes for trade-off analysis (Claude's discretion; draw from 04-RESEARCH — e.g. weights set or adjusted after scoring to favor a preferred option, too many criteria diluting the signal, adding criteria mid-analysis, treating a near-tie as a precision problem instead of finding the swing criterion, scoring criteria that are not independent).
