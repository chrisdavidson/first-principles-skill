## Executive Summary

**The question:** What is the smallest, risk-proportionate set of written and verified controls that lets the organisation show its pharmacovigilance literature-monitoring output is fit for regulated use? Qualifying the DistillerSR software is only one part of that answer: reviewer judgement, unwritten process rules and the hand-offs between systems can each make the output wrong (§1).

**Recommendation:** Treat this as remediating an existing compliance gap rather than a software qualification project: correct the past, write one global process, control the hand-offs, then qualify DistillerSR in proportion to risk (chains C2, C8, C7).

**Key findings:**

- The process was never truly outside regulation: weekly literature monitoring is already a legal pharmacovigilance obligation, so past screening needs a formal deviation and corrective action (chains C8, C2).
- Separate regional teams applying unwritten rules will judge the same article differently, so one global procedure with regional annexes and cross-region calibration is needed (chain C12).
- Awareness by anyone in any region starts the reporting clock, so each region's first-awareness date must be captured and each article given one owner to prevent duplicate cases (chain C13).
- The date the weekly search runs is day zero, which makes date capture and screening turnaround DistillerSR's highest-risk functions (chain C10).
- Systems that only carry data can be controlled by reconciliation at the boundary rather than validated (chain C4).

**Value and risks:** The work makes the output defensible at inspection with validation effort set by risk, not spread evenly across every system. The first compliant cycles will need more reviewer effort inside the weekly window, boundary controls only work if the checks run every week, and regional teams lose discretion beyond what local law requires (chains C7, C10, C4, C12).

**Band (from §6):** MEDIUM (chains C5, C7) — the platform's own controls have not yet been confirmed by the supplier.

**Would change it:** A supplier assessment confirming DistillerSR's audit trail, access controls, date capture, electronic signature and release terms (chain C5).

**Next steps:**

1. Open a deviation and corrective action, with a retrospective sample check of past screening (chain C8).
2. Write one global procedure covering the search strategy, screening rules and time limits, with regional annexes and calibration (chains C1, C10, C12).
3. Map the data flows, capture first-awareness dates by region, assign article ownership and reconcile the hand-off to the central safety system (chains C4, C11, C13).
4. Run the supplier assessment, then qualify DistillerSR with scripted evidence for date capture and other output-changing functions (chains C5, C10).
5. Set up release-impact, periodic review and archive controls (chains C6, C9).
