The agent recognized your instinct and named the technique for it — a **pre-mortem**: instead of asking "will this work?", you assume the plan has *already failed* and reason backward to every cause. That prospective-hindsight framing surfaces failure modes that optimism (and an excited team) normally suppress.

It's ready to run a full structured pre-mortem, but to make it sharp rather than generic it needs the actual plan. Specifically:

1. **The plan itself** — what you're building/shipping/deciding (a paragraph or a doc link).
2. **The hard constraints** — deadline, budget, headcount, compatibility, regulatory — anything non-negotiable.
3. **What "success" looks like** — how you'll know in N weeks/months whether it worked.
4. **What's locked vs. still movable** — so it knows which failure modes are actionable vs. ones you'd have to accept.

Once it has that, it will produce:

- **Problem Essence** — the core thing the plan must achieve, stripped of framing.
- **A failure-mode sweep** — every plausible blow-up, generated by category (people, process, technical, dependencies, market/external, assumptions) so it isn't just the obvious ones.
- **The adversarial pass** — for each failure mode: "would I have stayed quiet about this in the room?" The ones you'd suppress are the highest-signal.
- **Clustering** — where multiple failures share a root (over-optimistic timeline, single point of dependency, unvalidated assumption). Clusters are structural weaknesses, not isolated risks.
- **Findings → action** — for each weakness: change the plan, or consciously accept the risk with a named mitigation and owner. (Its line: "A pre-mortem that doesn't change the plan was theater.")
