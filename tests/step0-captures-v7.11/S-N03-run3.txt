For a startup crash, the usual failure-guaranteeing conditions are:

1. **Error handling that runs too late** — a bare top-level statement (import, module-level config load, global client init) throws *before* any `try/except` is reached. The most common startup-crash cause; no handler can catch what executes at import time around it.
2. **Catching the wrong exception type** — `except ValueError` wrapping code that raises `KeyError`/`FileNotFoundError`/`ImportError`, so the real error escapes.
3. **Swallowing then re-failing** — `except: pass` hides the root cause, but a later line depends on the state that the failed code was supposed to produce, so it crashes downstream with a confusing message.
4. **Missing-config / missing-secret at import** — env var or file read at module top level with no guard, raising `KeyError`/`FileNotFoundError` before `main()` runs.
5. **Handler that itself raises** — the `except` block references an undefined variable, logs to an unconfigured logger, or formats the exception wrongly, masking the original.
6. **Ordering / circular import** — error handling assumes a module is loaded, but an import cycle or a side-effect-on-import fails first.
