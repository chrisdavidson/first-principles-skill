## What's actually wrong with your error handling (the thing you're nervous about)

The crash is a symptom. The real weakness is that **the entire dependency-loading block at module top level (lines 76-85) has no error handling at all**, even though the script is explicitly documented to be copied around and run from `/tmp`. Surfacing the failure modes:

1. **No guard on the most fragile operation, run at the most fragile time.** The `importlib` load runs at import time, before `main()`, before `argparse`, before any try/except. So a missing sibling can never produce a friendly message — it can only produce a raw traceback. The docstring even advertises a clean exit-code contract (line 42: "exit code 2 = usage/environment error … stale agent body"). A missing core module *is* an environment error, but it bypasses that contract entirely and exits with an unmanaged code. Your stated error-handling intent and your actual behavior diverge here.

2. **`spec_from_file_location` can silently return `None`.** If `_CORE` doesn't exist or isn't loadable, `_spec` can be `None`, and `_spec.loader` then raises `AttributeError` instead of a clear "file not found." Here you happened to get a clean `FileNotFoundError` from `get_data`, but on a slightly different failure (unreadable path, bad permissions) you'd get a misleading `AttributeError` masking the real cause. The `# type: ignore` comments on lines 78 and 80 are suppressing exactly the type-checker warnings that flag this.

3. **No existence precheck despite knowing the exact dependency.** The code knows `_CORE`'s absolute path on line 76. A single `if not _CORE.exists():` check could print "expected `_battery_core.py` beside this script — run from `$REPO/scripts/` or copy it alongside" and `sys.exit(2)`, honoring the documented contract. Right now a user gets a 5-frame `importlib._bootstrap_external` traceback that points at frozen stdlib internals, not at the real problem (a misplaced file).

4. **Four attribute pulls (lines 82-85) assume the module loaded fully and exports those names.** If `_battery_core.py` exists but is stale/partial (a real risk — the docstring at line 42 itself worries about "stale agent body"), these raise `AttributeError` at import time, again outside any handler.
