## Pre-mortem frame it gave you in the meantime

Scan your own startup code against these recurring error-handling failure modes:

**The crash is in the error handling itself**
- A broad `except` that catches the real error then fails inside the handler (you see the handler's error, not the cause)
- A handler referencing a variable that was never defined because init failed (e.g. logging `config.path` when `config` didn't load)
- `sys.exit()` / `raise SystemExit` in a handler making a recoverable error look fatal

**Error handling runs too late**
- Import-time code (config reads, env vars, DB connections, file opens) running *before* any `try/except` in `main()` can protect it

**Swallowed errors surfacing later**
- An early `except: pass` hiding a failed init, then a downstream crash on the half-initialized object

**Environment-shaped failures often misread as "error handling"**
- Missing env vars / `.env`, wrong working directory, wrong virtualenv (`ModuleNotFoundError`), circular imports
